# 重大变更专项检查

复用当前任务的规格、计划和讨论，检查风险、关键契约、兼容与失败恢复、规格到任务及验证的映射。起草时补齐这些内容；已有文档按原结构修订。本技能服务于仓库开发，维护在 `.agents/skills/`，与产品运行时的 `skills/` 分开。

## 先确定范围

1. 从根目录 `AGENTS.md` 和任务入口读取相关规则、当前代码／测试、适用规格与计划；存在 `CLAUDE.md` 时一并遵循。按 [领域文档](../../../docs/agents/domain.md) 读取术语与相关 ADR，确认权威来源和替代关系。讨论稿中的建议、已确认决策与当前实现分别识别。
2. 按 [Gate 1：影响分级](references/gates.md#gate-1影响分级) 区分普通、定向契约审查、重大变更。按本次行为和兼容影响判断；信息不足时先核查具体受影响边界，不因文件数量或技术未知直接扩大检查范围。
3. 按下表完成用户要求的文档模式。关键结论和证据已有记录时链接复用，沿用已确认的决策与授权。

| 本次任务 | 完成条件 |
| --- | --- |
| 起草／增量修订 | 受影响规则、契约、兼容结论和验收要求清楚；新增业务规则先写入规格，再安排实施 |
| 只审查 spec | 按严重度给发现、证据和结论；缺少 plan 不阻碍交付本次规格审查，只审查时保持只读 |
| 审查 plan／准备实现 | 核对适用规格、任务和验证是否一致；重大变更完成 Gate 5／7／8 的适用项，定向审查只核对受影响项 |
| 探索／基线 | 记录事实、未知、影响及后续入口；技术未知可在已有授权范围内先做隔离探针，再决定产品实现 |

## 检查与收口

- 具体检查读取 [Gate 手册](references/gates.md)，按模式和风险选择适用项；手册中的 CowAgent 示例只在命中相应边界时使用。
- 冻结可观察业务行为、对外及持久化契约；私有辅助函数、局部变量和同范围内的实现组织留给实施决定。
- 关键业务取舍未定或兼容／恢复缺乏依据时，明确受阻任务并补充决策或探针；其余独立工作可继续。已知证据能解决的问题直接修订，只有需要用户作新的实质选择时才提问。
- 文件清单记录预期影响面。同任务的必要辅助文件或测试补入执行安排后复核即可；改变业务、权限、兼容、外部副作用或超出授权范围时，回到受影响的契约检查。
- 文档交付记录发现、适用检查结论和剩余问题；实现交付再补实际验证及偏差。文档自审通过不等于产品测试通过，也不增加实现、提交或发布授权。

## 产物与协作

规格与工单遵循 [任务落点](../../../docs/agents/issue-tracker.md)，术语与架构决策遵循 [领域文档](../../../docs/agents/domain.md)。规格、计划和工单中的实施细节各有唯一正文，其余入口链接复用；执行安排可直接采用现有工单。需要独立实施计划时，沿用或按需创建 `docs/codex/plans/` 下的对应文档；讨论稿待规则收敛后再形成可实施规格。

只有用户要求起草且没有适用文档结构时，才按需取用 [规格模板](references/spec-template.md) 或 [计划模板](references/plan-template.md)；已有工件不为套模板重写，小改动不另建整套文档。

本技能补充当前讨论、规格、拆票、实施和审核流程，不要求安装额外技能，也不为每个阶段增加人工批准。验证方式随改动选择，不强制 TDD、全量测试或提交。只维护本目录一份；这里的 Gate 是代理执行的检查，只有实际接入并运行的脚本才能报告为自动门禁。
