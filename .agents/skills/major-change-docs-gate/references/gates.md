# 重大变更检查手册

按任务模式和风险选用检查，沿用 Gate 0～9 编号。只记录适用结论，证据可链接已有章节；多个检查共用同一份规则、任务与验证映射。

## Gate 0：事实基线

确认本次文档模式、范围、当前实现及测试、适用规格／计划、权威来源和替代关系。按项目导航展开相关材料，沿用领域术语及相关 ADR。区分期望规则、已确认决策、讨论稿建议、当前实现和历史记录。

## Gate 1：影响分级

按行为、兼容和故障影响判断，文件数量和是否跨层不单独决定级别。已有重大规格的局部修订，按本次改变的契约分级。

| 级别 | 判定依据 | 文档与检查范围 |
| --- | --- | --- |
| 普通 | 局部样式／文案、内部改名、已证实公共行为不变的重构，且不改变权限、兼容或外部副作用 | 使用现有任务和必要验证，退出专项检查；无需新建 spec／plan／Gate 表 |
| 定向契约审查 | 边界清楚的兼容增量；例如新增可选返回字段，缺省及非法值处理明确，旧读写器、回滚和数据保留行为均有依据 | 在现有规格／计划、工单或一份简短记录中检查受影响契约、兼容和验证映射；不要求整套工件或全量表格 |
| 重大变更 | 改变唯一真相源、任务终态、权限边界或跨入口一致性；破坏性 API／IPC／事件／文件变更；迁移影响历史数据；外部写入、并发或恢复可能造成数据丢失、重复不可逆操作、错误权限或结果失真 | 完成适用契约和失败恢复审查，准备产品实现前完成 Gate 5／7／8；规格结论与执行安排都需可定位 |

信息不足时，先核查受影响的调用方、读写路径及现有验证，必要时做有界探针。涉及旧数据写入、身份／授权变化或不可逆外部操作，而关键兼容或恢复语义仍未清楚时，按重大变更检查该受影响范围。一般技术未知可拆为探索任务，不单独触发完整产品规格流程。

CowAgent 分级示例：

- 调整模型设置页的悬停文案属于普通改动；增加旧调用方可忽略的可选展示字段，且兼容已有依据时，做定向审查。
- 改变长期收录／临时使用规则、资料版本与引用失效语义，或让多个写入入口遵守新的统一规则，按重大变更检查。
- 引入持久任务状态与重启对账，改变工具授权或资料外发范围，或切换 Embedding 时迁移索引语义，按重大变更检查。
- 重试与外部写入的局部修复，按是否改变幂等、恢复或副作用契约判断，不因涉及这些词就统一升级。

## Gate 2：关键决策

明确本次受影响的真相源与读写责任、业务行为、旧对象处置、验收要求。状态、幂等、并发、超时重试、权限及外部匹配命中时给出可执行结论；精确匹配写清比较键、规范化和唯一性判据。

关键业务取舍不能留给实现猜测。技术可行性未知可以拆为隔离探针；产品任务依赖其结果，未知项和通过标准需可追踪。已确认结论直接复用，提案与 ADR 冲突时指出受影响决策及重新讨论的理由。

## Gate 3：适用契约

只覆盖实际受影响的边界，沿用现有类型／schema 等权威定义并补足行为语义：

- 对外／持久化字段、枚举、版本和业务动作：类型、必填、缺省、非法值、旧版本读写和数据保留。
- 状态及写入：前置条件、成功、业务阻止、失败、副作用、幂等与并发。
- API／IPC／事件／任务：输入输出、错误、超时重试；异步结果的会话／修订归属及迟到处理。
- 权限和界面动作：适用时区分隐藏、禁用、可执行，沿用项目界面约定。
- 迁移、原子写入、外部副作用：适用时明确故障后的数据状态、回查、回滚／恢复以及验证办法；安全、性能和可观测性有实质影响时记录约束。

按涉及能力补充 CowAgent 特有边界；这些是检查线索，不是所有任务的必填表：

| 涉及能力 | 核对重点 |
| --- | --- |
| 资料与知识引用 | 原件、解析稿、文档版本与引用位置的关系；临时使用、更正、替代与撤回如何影响检索和回答；保存成功与可检索的回执是否区分 |
| 消息与持久任务 | 消息／附件的去重键和归属；接收、执行、取消及终态；重启后如何回查、重试及避免重复外部操作 |
| Provider 与索引 | 能力绑定、配置刷新及进行中任务的生效语义；更换 Embedding 模型／维度时的索引兼容、重建与切换 |
| 工具与外部软件 | 调用身份、可访问资源、实际副作用、执行范围，以及失败或结果未知时的查询与恢复 |

具体业务结论以本次规格及已确认 ADR 为准。私有函数、局部变量和普通内部实现不要求逐项冻结。不相关主题可用一句范围说明排除，无需复制空表或逐格填写 N/A；受影响契约不能因未使用模板而省略。

## Gate 4：起草或修订 spec

复用唯一规格正文，写清问题、目标／非目标、关键行为、适用契约、验收标准及替代关系。增量只修改受影响章节并说明兼容结论；多项规则需要追踪时使用稳定 ID。模板是缺少既有结构时的参考。

## Gate 5：spec 审查

检查规则矛盾、关键业务空白、失败及兼容缺口，证据是否支撑契约可兑现。按严重度给问题、来源、影响和修订建议。纯 spec 审查在此可交付，Gate 6～8 不因缺少计划而成为本轮文档任务的前置条件。

## Gate 6：起草或修订执行安排

每个实施任务能定位规格、目标、预期文件／模块、依赖、验证方式和通过标准。执行安排可以采用现有计划或工单；已有任务覆盖时不另建 plan。计划与工单通过链接引用唯一的实施细节，保留各自必需的目标、状态和依赖。计划中的业务新增先回写规格。

## Gate 7：plan／工单审查

检查关键规则是否都有任务和验证、依赖是否可执行、预期文件是否覆盖影响面。验证按任务选择 TDD、回归、静态、人工或演练，不统一要求全量测试；仓库既有必需检查仍按适用范围执行。有意义的依赖验证失败时，先修复再进入依赖它的任务。

同范围内的必要文件补入执行安排并复核，不重新请求既有授权；业务、权限、兼容、外部副作用或授权范围改变时重开相关检查。提交按已有授权与项目日志约定处理，不作为每个任务的默认步骤。

## Gate 8：规格／执行安排一致性

准备产品实现时，核对受影响规则都有任务与验证，且没有规格外行为；比较公共字段、版本、错误、状态、会话归属、兼容与恢复语义。重大变更的 Gate 5／7／8 适用项无阻塞后才能进入相关实现；定向审查用简短映射即可。缺口阻塞相关任务，隔离探索及其余独立工作可按授权推进。

## Gate 9：交付证据

文档交付记录本次检查结论、证据和未决问题，不要求为文档审查执行产品测试。实现交付补实际验证、偏差、剩余风险及适用的迁移／恢复结果；任务状态按项目工单规则维护，文档审查结论与工单状态分开记录。已授权提交按项目要求更新日志，契约改变时回写规格并复核受影响项。

## 记录方式

普通改动无需 Gate 表；定向审查可用一段结论。重大变更的适用项可复用原有证据表或采用下列格式，不强制列满十行，不为每个 Gate 新建文件或交接轮次：

| 检查／Gate | 结论 | 证据 | 评审者／日期 | 未决项及受影响任务 |
| --- | --- | --- | --- | --- |
| <适用项> | PASS / BLOCKED / 未检查 | <章节、文件、实际命令输出或审查记录> | <评审者／日期> | <问题或无> |

PASS 只表示该项检查已完成。未运行的验证写“未运行”，模型自审、文档完整和产品验收分别记录；本表不能替代原始证据或代码审核。
