## 执行边界

- 规格唯一正文保存在 `.scratch/<feature>/spec.md`，计划和工单承接实施与验证；发现新增业务取舍时，先修订受影响契约并明确其确认状态。
- 术语沿用根目录 `CONTEXT.md`，架构决策链接 `docs/adr/` 中相关 ADR；与既有决策冲突时记录冲突及重新讨论理由，不在计划中另立一套定义。
- 文件清单是预期范围。同任务必要的辅助文件或测试补入执行安排并复核即可；业务、权限、兼容、外部副作用或授权范围扩大时，复核受影响契约及授权边界。
- 关键验证未过时不进入依赖它的任务。验证范围按实际影响选择，沿用已确认的接口边界和会话已有授权。

## 兼容与恢复安排（按需）

仅在规格涉及相应影响时，安排迁移、隔离探针、恢复或回退任务，并映射到规则与验证入口。例如：

- 资料来源／版本变化及撤回：原件定位、知识引用、缓存和索引更新，必要片段的云端处理边界。
- 消息或任务执行变化：重复投递、部分成功、幂等副作用、任务重启恢复点。
- Provider／索引变化：旧配置和能力兼容、索引升级／重建、回退与引用连续性。

复用规格中的契约及相关 ADR 链接，此处只写实施安排与验证，不重复业务正文。无对应影响时删除本节。

## 一致性与交付

记录关键规格到工单和验证的对应关系，可直接复用上表或工单内容；受影响的兼容、失败恢复及跨边界语义均有承接。

实施后填写实际验证与证据、偏差及剩余事项。未执行的验证明确标注，未完成的任务保持可见；文档审查完成不能记为产品实现完成。本模板不增加审批、全量测试或提交前置要求。
