# 个人助手首期规格

文档状态：可执行，按任务依赖完成技术前置。日期：2026-11-10（Asia/Shanghai）。维护：Codex 与用户。

本规格覆盖改造方案 A/B 阶段及后文注明日期的资料／知识增量。用户已要求提交首期方案并交由另一会话执行；既有自主知识整理原则继续沿用，不增加收录审批流程。下文契约作为实施依据；方案提交 `990f9ba1` 当时仅交付文档；后续实施与产品验证单独记录在[首期交付记录](../../docs/codex/logs/2026-11-10-个人助手首期交付.md)，不以文档检查代替实际验收。第 5.8／5.9 节是 2026-11-11 制定的文档读取与知识检索方案，尚未作为产品实现验收通过。

## 1. 权威来源与范围

- 用户在当前讨论中确认：本人使用；本机在线期间可用；复用官方 Windows 界面；文本 PDF、Word、Excel 同批；原件本机、必要内容可用于指定云端模型；各能力独立配置 Provider。
- 最新保留选择按用户明确文字“先保留完整的看看”解释：会话、附件和处理记录完整留档，首期不自动清理。
- 定制版使用独立数据目录，从空目录开始；当前没有历史官方数据迁移需求。
- 领域术语见 [CONTEXT.md](../../CONTEXT.md)，资料与云端推理边界见 [ADR-0001](../../docs/adr/0001-local-sources-cloud-context.md)。
- [原方案与执行安排](../../docs/codex/plans/2026-11-10-个人助手改造方案-讨论稿.md)保留架构、阶段、任务与验证安排。本规格是首期行为、持久化及兼容契约的唯一正文；发生差异时先按用户最新选择修订本规格，再同步计划。
- 基线为 `a8658548`。该提交增加仓库开发技能；业务能力核查沿用 `83ce29c3` 与此前调研，不把文档中的建议当成已实现功能。

首期交付：可本地安装的 Windows 桌面程序；本人可在原模型设置页配置中转，在飞书发送资料并获得有出处的回答，重启后仍可查询接收记录、资料与处理结果。

后续范围：Codex 编程执行器、RFLink 业务接口、微信、更多飞书业务、Office/PDF 编辑输出、建模。首期不实现这些后续能力，不部署 GBrain 或 LangGraph。Embedding、ASR、TTS、绘图沿用独立配置入口；只有实际启用的能力才要求端点联调，未选供应商不阻塞首期文本资料流程。

影响级别：**重大变更**。首期改变资料写入责任、版本与引用、任务终态、多个入口的一致性及持久数据恢复，需完成适用的 Gate 5/7/8 后才进入相关产品实现。

## 3. 身份与入口（PA-02）

实施契约：

- 本人身份由受信配置登记，飞书使用 `channel_instance_id + app_id/tenant_id + sender_open_id` 作用域内的绑定；不能用昵称、“我是主人”的文本或模型参数授予身份。
- 绑定在本机已认证设置入口完成。未绑定时飞书保持未就绪；收到其他身份的消息时在下载、模型推理、检索和工具执行之前拒绝处理。首期只接受本人私聊。
- 本机绑定入口可生成 5 分钟有效的一次性绑定码，临时连接选定的已配置机器人；仅从该应用的真人私聊文本验证绑定码并提取实例、App、tenant_key、sender_open_id。候选只保存在进程内，由桌面认证入口显式“确认为本人”后才写入绑定；普通消息、附件、群聊与错误绑定码不能触发下载、任务、模型、知识或工具，也不自动认领第一个发送者。过期、取消、重启或重新生成使旧码和候选失效，更换 App 后不能确认旧候选；绑定消息不作为业务资料留档。
- 重新绑定期间，所选渠道只接受绑定握手，旧本人也不能提交新业务；取消或过期后恢复原有有效绑定，首次未绑定仍拒绝业务。绑定命令的重投及超长文本不得回落业务留档；任何配置或渠道名册保存都会使未完成握手失效，保存绑定前在配置写锁内再次核对修订，防止 App 切换又还原后复用旧候选。
- 本机沿用桌面 token 与现有 Web 认证。进入任务／收录模块前将来源绑定到同一内部 `owner_id`，模型无法通过传入另一个 `owner_id` 改变归属。
- 已有通用渠道能力保留；本人限制作用于这次独立定制实例，不默默改变其他已配置 CowAgent 实例。
- 任务状态、原件打开、知识读取、通知重试、取消和恢复均核对归属，不能只在消息入口校验一次。

## 4. 持久接收、任务和回执（PA-04、PA-10）

### 4.1 可观察数据

以下定义是新增入口与持久记录的 v1 行为契约，不要求内部函数或数据库表采用同名组织。

| 数据 | 类型／必要性与语义 |
| --- | --- |
| `schema_version` | 整数，新增记录为 1。未知大版本拒绝写入并说明所需版本；不能按空库覆盖。 |
| `receipt_id / task_id / request_id` | 非空不透明字符串，系统生成或校验；重试复用同一 request_id。 |
| `owner_id / origin` | 受信入口注入；origin 记录渠道实例、消息、附件及本机来源。 |
| `document_id / revision_id` | 逻辑资料及不可变内容版本标识；首次接收可为空，绑定后持久保存。 |
| `status / stage / attempt` | status 使用下表任务状态；stage 使用 receive/download/decide/parse/publish/pending_index/done，说明当前或失败步骤；attempt 为从 1 起的尝试次数。pending_index 是阶段，不新增同名任务状态。 |
| `outcome` | 成功时必填：`published / transient / duplicate`，明确是否产生长期可检索知识。 |
| `error` | 失败时含稳定 code、阶段、简短说明与可否重试；不包含密钥。 |
| `created_at / updated_at` | 有时区时间；持久化统一 UTC，界面按 Asia/Shanghai 显示。 |
| `config_revision / result_refs` | 本次能力配置版本及结果定位；仅保存非敏感配置标识。 |
| `notification` | `pending / sent / failed / unknown`，与业务任务终态分别保存。 |

缺失来源、未知状态／动作、无权 owner、非法路径或无效期望修订必须在副作用前返回错误。任何来源路径均校验属于本次接收记录或授权工作空间，不接受模型任意指定本机文件作为某人的附件。

### 4.2 去重与状态

- 飞书事件接收键为 `owner_id + channel_instance_id + message_id`；附件键再加协议中的 file_key，协议无稳定附件 ID 时使用该消息内稳定序号。仅收到元数据时先登记，附件下载完成才标记“原件已保存”。
- Web／本机提交使用入口生成的 request_id。相同键和相同请求返回既有 receipt/task；相同键但请求内容不同返回 `idempotency_conflict`，不能覆盖原任务。
- 文件 SHA-256 仅用于原件字节去重；文件名、主题相近或相同哈希都不能单独证明“替代哪个逻辑资料”，详见第 5 节。
- 事件处理先持久登记并入队，再异步下载、解析和索引；回调成功与用户可见的“已接收”不能先于本地接收记录提交。落盘失败不能宣称已接收。

| 任务状态 | 含义／合法后续 |
| --- | --- |
| `queued` | 接收记录已保存，待执行；可进入 running 或 cancelled。 |
| `running` | 正在下载／判断／解析／发布；可进入 waiting_input、succeeded、failed、cancelled、needs_reconcile。 |
| `waiting_input` | 等待资料用途、版本等具体信息；补充后回到 queued，或取消。 |
| `succeeded` | 本次目标完成，outcome 与 result_refs 可回查；published 必须满足 PA-08。 |
| `failed` | 已知失败及阶段明确；显式重试在同一任务增加 attempt，不创建重复操作。 |
| `cancelled` | 取消已生效；此 attempt 的迟到输出不能发布。 |
| `needs_reconcile` | 重启或超时后无法确定步骤结果；先核对已有文件、发布记录或远端回执，再继续或失败。 |

取消请求只有在完成本地状态切换后才显示“已取消”。已发布成功的任务不能用取消撤回资料，须使用 PA-09 的撤回动作。运行中的取消按提交屏障判断胜者；取消先提交则后续回调失效，发布先提交则返回已完成。第 5.8 节的多批读取任务中，本句的“已完成”指整任务完成提交；部分批次发布不使整任务终态化，取消仅停止尚未完成的工作，已发布部分保留。

### 4.3 重启与通知

- 启动扫描非终态：尚未执行的本地操作可继续；处理中记录先 needs_reconcile，通过原件哈希、解析清单、发布提交标识和索引世代核对完成点。可证明幂等的本地阶段才重试。
- 本机已登记任务的恢复优先于飞书积压过滤；现有启动前消息过滤不能丢弃这些任务。未曾登记的离线期间消息不属于首期可靠接收承诺。
- 任务结果已落盘但通知失败时，任务仍成功，通知保留重试状态。能确认失败的发送可重试；发送结果未知时复用远端幂等标识或先回查，不承诺无条件的“通知恰好一次”。
- 通知只发回登记的本人会话；重绑渠道或迟到事件不能改变归属。任何通知失败均不导致重新收录、重新执行或丢弃结果。

### 4.4 动作与界面回执

提交返回 receipt_id、task_id 及当前状态，不直接返回“可检索成功”。查询返回归属核验后的状态、阶段、尝试、错误、结果与通知状态；重试、取消和补充输入均按既有 task_id、当前 attempt 与期望状态校验，状态冲突返回最新状态，不覆盖已完成结果。相关错误至少区分 invalid_request、forbidden、idempotency_conflict、version_conflict、config_unavailable、parse_failed、limit_exceeded、needs_ocr、index_failed 和 storage_failed。

本人界面中：等待输入时显示补充入口；可重试失败显示重试；queued/running/waiting_input 显示取消，取消生效前显示处理中；成功后可打开原件、引用与处理结果，撤回独立显示。终态任务不提供无效的取消动作；无权限的对象不展示操作，也须在调用层拒绝。文件已保存但索引失败应显示“已保存，待索引”，任务为 failed、stage 为 pending_index，重试只接续未完成阶段。必要说明沿用问号悬停方式。

## 5. 资料身份、解析与发布（PA-05、PA-06、PA-08）

### 5.1 数据职责

- **权威记录**：原件、来源与版本登记、用途决定、当前发布指针、任务与处理回执。
- **可重建数据**：解析稿、出处映射、知识投影、检索索引；重建必须保留对应解析器版本与语义关联。
- 原件与历史解析稿放在默认知识扫描范围外；当前知识投影进入现有知识目录。完整归档不能被扫描器顺带纳入长期召回。
- 新增“托管知识页”必须带系统可核对的 source/revision/parse/publish 关联。已有未托管 MD/TXT 继续按旧逻辑读取，显示其来源粒度，不伪造原件和页码。

### 5.2 身份和并发

- document_id 表示逻辑资料；revision_id 表示该资料的字节版本，关联原件 SHA-256、原文件名、媒体类型和来源清单。相同原件字节可共用存储，来源记录分别保留。
- 已明确同一资料及同一哈希的重发复用版本，返回 duplicate。未能唯一确定逻辑资料时保留独立接收记录并让 Agent 澄清，不能按文件名覆盖。
- 替代／更正请求带 expected_current_revision；与当前不符返回 version_conflict，原当前版本不变，候选保留供核对。两个并发版本不能互相覆盖。
- Agent 可根据对话确认新旧资料关系；关系不确定时保留为候选。字段中的“期望修订”仍由程序核验。
- 用途决定、撤回、更正和重新发布各有可比较的状态修订；候选记录生成时所依据的状态修订。发布提交时同时校验内容版本与用途/有效状态未变，不能只比较原件 revision_id。
- 解析记录含 parser_id/version、解析配置及原件哈希。出处映射与解析文本不可脱离版本单独覆盖。

### 5.3 首批格式与限额

| 格式 | 首批引用位置与行为 |
| --- | --- |
| 文本 PDF | 1 起的文件物理页号，必要时附原文片段；与印刷页码不同则明确标识。无可提取文本时返回 needs_ocr，不能把空结果标成成功知识。 |
| DOCX | 章节、段落或表格行列位置，绑定解析版本；首期不以未排版的固定页码冒充引用。 |
| XLSX | 工作表和单元格／区域；分别标明公式和已有缓存值。缓存缺失说明无可用值；知识导入不重算公式、不执行宏或外部链接。 |
| MD/TXT | 沿用内容与行／章节定位。 |

旧 .doc/.xls、Excel 重算不在首期已交付承诺中。2026-11-11 已有增量接通 PDF 页面渲染与已有 vision，覆盖扫描页、混合页面及矢量图表；原文文字、OCR 转写与视觉解释分别登记。模型不可用、失败或预算未覆盖的页面明确记录，不把文本提取成功称为整份资料已完整理解。视觉调用沿用任务接收时的模型配置和授权范围。拟实施的原生读取、PPTX 及有条件旧格式支持见第 5.8 节；该节实施后替代默认全页逐次视觉的读取策略，不删除原能力与历史记录。

首期沿用当前飞书下载的 100 MiB 上限；发布文本受现有知识单件 10 MiB、批次 200 MiB/100 件约束。新增解析按预算限制页数／单元格和输出，具体实现预算由样本探针记录，不能无提示截断后发布。超限、加密、损坏或结构无法可靠定位时保留原件，返回明确失败或需补充能力；解析全文与展示分页分开。

### 5.4 发布成功

发布顺序：原件持久保存 → 解析与出处映射完成 → 候选知识登记 → 当前检索所需索引构建与校验 → 提交有效发布指针 → 返回可检索回执。

2026-11-11 起，新增长期收录必须提交第 5.5 节的整理成品；旧原文投影仅保留兼容与追溯，不能继续作为新增知识整理的替代路径。

- 文件保存回执不能替代索引可用回执。索引失败保留 pending_index，可单独重试；不重新下载或覆盖原件。
- 新版本未发布成功前，旧已发布版本继续有效。撤回／已证实失效的旧版本除外，不能在新版本失败时自动恢复使用。
- 更新发布时检查 expected_current_revision，发布指针和可见性由一次提交决定。候选暂存位置、内部表和锁实现由实施决定。
- 更正、撤回或用途变为临时后，已有候选立即失去发布资格。旧解析/索引结果即使在稍后完成或重启后恢复，也只能留档；恢复长期发布须有新的明确操作及状态修订。
- 所有读取入口先验证发布登记和知识投影哈希；托管页被旧接口、通用工具或外部编辑器直接改动时，标为未发布变更并重新处理，不能把它当成带旧出处的新事实。
- Web 导入、桌面导入、Agent 工具与原知识服务对托管页复用同一发布入口。系统提示、knowledge-wiki、write/edit 和后台摘要需要对齐；只改提示不算兑现本契约。

### 5.5 主题知识页与视觉覆盖（2026-11-11 增量）

- 主 Agent 按上下文自主决定用途，并实际读取 knowledge-wiki 后完成提炼、分类、命名、主题拆页、跨资料合并及已有页更新。程序接收标题、分类、正文、关联与出处，不根据文件名或解析全文生成替代知识成品。
- 资料与知识页为多对多关系。知识页有稳定身份和不可变发布版本；更新须核对预期页版本，正文块关联真实来源版本、解析版本及原文位置。相关页面链接与作为论据的派生依赖分开登记，派生依赖可追到原件。
- 一次完整整理的候选及依据快照持久化；发布原子提交知识页版本、关键词索引与有效指针。先回读核验索引，再显示“可检索”；索引失败可接续，不重新生成已保存成品。重启复核全部来源状态和上游页版本，迟到结果不能恢复失效内容。
- 来源更正、撤回、替代或改为临时时，受影响整页及派生内容立即暂停作为有效依据；无关页面继续使用。来源恢复不自动恢复旧页，须基于仍有效依据重新整理并核验发布。历史页与出处保留当前失效状态。
- 只发布由已读取证据支撑的内容。存在视觉未处理范围时，知识页可在有效且索引核验通过后显示“可检索”，资料另行显示视觉待处理页号及原因；依赖未读取图表的结论暂不发布。OCR 与视觉解释保留其类型，不能冒充原文文字。
- 同来源新原件登记仅形成候选，新版发布成功前保留旧有效知识；已明确更正、撤回除外。原文投影一旦由主题知识发布接替，不因主题页暂停而恢复有效；升级前的原文候选也不能覆盖主题整理。
- 普通知识问答接触托管来源后，其派生内容同样遵守来源契约；问答不另写无出处知识、记忆或日记。确需持久化的新结论走受控发布，关联来源与上游页版本；重启或后台摘要不能绕过。
- 界面以合理标题、分类和知识页关系呈现；内部编号、来源元数据及位置 JSON 留在接口或诊断信息中。支持查看原件及可读原文位置，图谱不能替代原件或收录回执。说明沿用问号悬停。
- 兼容当前定制版已有来源、任务和未托管页，无需重新上传。当前仅一份既有资料，复用已登记原件重新整理；不建设批量迁移。新知识发布失败保留原有效旧结果，成功后避免旧投影与新知识重复召回。
- 首期仅关键词索引，无 Embedding 请求。真实账号与模型验收本次通过源码调试启动执行；须区分离线替身结果、真实模型结果及尚未覆盖项目。

### 5.6 资料视图、分类与历史（2026-11-11 界面增量）

用户经 grilling 确认以下行为，取代按每次处理任务平铺全部操作的展示：

- **资料视图**：以逻辑资料集中展示当前用途、有效性、视觉范围和关联知识，处理任务及尝试完整保留在历史。已登记资料按 document_id 归并；未登记的接收附件保留独立身份，仅有明确任务父子与附件关联时归并，不能凭同名或相同字节合并不同逻辑资料。多附件分别展示；无原件的知识整理任务保留独立处理记录。列表与详情分栏，窄窗口进入详情并可返回；状态、视觉结果和来源动作不在每个知识页下重复。
- **来源管理**：原件与重新整理为常用动作，更正、用途和撤回集中在来源管理；说明其对关联知识及派生页的影响。沿用既有权限、版本、取消及失效规则。当前有效结果与最新处理失败分开呈现，失败不能把仍有效的旧知识标为不可用。
- **手动分类**：分类作用于知识页，不作用于整份原件。本人可从已有分类选择或新建分类，独立持久保存 manual/auto、单调递增分类修订和审计事件。手动分类保持到显式恢复自动；恢复自动只解除锁定，当前分类保留，后续 Agent 整理可调整。分类修改不请求模型、不改知识正文、原件、出处或内容版本，不使依赖该页的知识失效；自动发布及所有展示／检索回执遵守手动选择。修改须校验当前知识页版本与分类修订，冲突不覆盖；分类非法、对象非当前有效或无权时拒绝。
- **导航与历史**：知识索引为按有效分类组织、可搜索的当前目录；整理记录为真实事件时间线。历史项打开对应发布的只读内容，明确当前／历史／暂停状态，提供存在的当前有效版本入口；历史可读不等于可检索。历史回读核验原发布内容和出处，不绕过当前有效性守卫，也不修改旧发布。没有历史依据的数据不补造时间或事件。保留原有索引／日志文件及未托管内容，旧数据无需重新上传；旧页缺少分类设置时默认自动。
- **界面与链接**：系统索引／日志页不显示“未分类”；使用现有主题、图标、表单与提示，说明收进问号。应用内知识链接解码并按当前文档位置解析，兼容中文、空格、嵌套相对路径、查询和锚点；同名文件不得被错误猜中，未找到明确反馈。分类作为页面组织元数据，与不可变发布文件路径分离，分类改变后当前目录、侧栏、标题、图谱及检索回执一致，旧引用继续可追溯。

新增目录、分页事件与历史版本读取接口均沿用当前 Agent 工作区及鉴权；分类动作复用 knowledge action 入口并独立提交。新增字段与附加表兼容原 v1 数据，原子保存、重启与完整备份恢复覆盖分类设置和事件；目录投影写失败不回滚权威状态，后续可重建。验收覆盖资料归并边界、状态分离、分类锁定／恢复／并发／重启、历史失效只读及原件哈希、中文链接与同名路径、深浅主题和窄窗口键盘操作。

### 5.7 每篇知识的一句话摘要（2026-11-11 增量，PA-14）

用户要求补回每篇知识的摘要，并允许复用当前唯一资料重新生成知识库。本节补充第 5.5／5.6 节：摘要属于知识页的内容版本，分类仍是独立组织元数据；原件、出处、发布有效性及历史保留规则继续适用。

- **内容与生成**：主 Agent 实际读取资料并整理主题知识时，为每篇知识写一句话，说明其主题、范围或用途；建议 30～60 字，避免重复标题或只写“介绍相关知识”。摘要以本页正文为依据，不加入正文没有的结论、数值或未核验图表解释。多篇知识各写摘要，一份资料的任务摘要不能代替各页摘要。
- **写入契约**：新增或更新知识页的工具输入 `pages[].summary` 为必填字符串；去除首尾空白后为 1～160 个 Unicode 码点的单行纯文本，禁止换行及控制字符。缺失、类型错误、空白或超长在候选副作用前返回 `invalid_request`，提示重新提交；不静默截断，不取标题、分类或正文首段冒充。现有顶层 `summary` 继续保持旧参数兼容含义，不能替代 `pages[].summary`。
- **版本与读取**：摘要随候选、不可变发布记录、幂等结果和历史版本持久化；知识正文更新时提交相应摘要。目录、发布回执、资料关联知识及历史版本读取统一返回该版本摘要，不临时调用模型生成。当前页采用当前发布摘要，历史页保留当时摘要；修改分类保持摘要及内容版本不变。目录和助手上下文继续排除失效页，历史摘要不进入当前目录。
- **兼容**：旧发布、升级前已持久化候选及成功回执允许没有摘要，读取按空字符串处理。原任务配置可用且依据未变时，恢复沿用已保存成品，不因升级重新请求模型；原配置不可用则按现有契约保留候选并阻止自动发布。有附件任务可显式按当前配置重新处理；无附件综合任务在新普通 Agent 会话重新核验版本后，按当前配置提交新任务，旧任务与候选保留，不称为接续旧候选。升级后发起的新整理输入遵守必填规则；旧调用方须刷新工具 schema 并提供每页摘要，缺失时明确报错。新字段作为现有 v1 记录的兼容增量保存；旧前端可忽略，新前端也兼容旧服务缺失字段。未托管页已有索引摘要继续保留；托管旧页缺失时不从旧索引的分类后缀猜摘要。不为本次单份资料建设批量迁移或摘要独立编辑入口。
- **索引与搜索**：按当前有效分类分组生成 `knowledge/index.md`，每条为 `[标题](路径) — 一句话摘要`；保留未托管内容和摘要，旧托管页缺摘要时仅显示标题。索引和 API 均从同一发布记录派生；投影失败按现有恢复规则重建，不另存一份可独立修改的摘要。桌面目录和网页知识列表搜索均匹配标题、有效分类与摘要；正文检索继续使用已有带出处的内容索引，摘要不成为独立事实块。
- **界面**：主知识目录在标题下直接显示摘要，最多两行；侧栏紧凑目录保持单行标题，通过悬停或键盘焦点访问完整摘要。缺摘要的旧页保留既有标题显示，不添加重复占位说明。沿用语义主题，长摘要、窄窗口和同名页面均可正确浏览与打开；规则说明放问号提示。
- **助手上下文预算**：保留小索引 8,000 字符完整注入和目录段 20,000 字符上限。超过 8,000 字符时，每条摘要紧凑为最多 40 字符的预览并标明缩略，保留完整标题、链接及分类组织；不得统一删除全部摘要。紧凑后仍超上限时按完整条目省略并报告数量，不截断链接。提示助手通过 `read` 分页读取完整索引或用 `memory_search` 找页，再回读知识及有效出处；缩略摘要只供选页。中文及英文提示一致，路径锚定和有效性过滤继续生效。
- **现有资料重整**：实施验收使用当前已登记的一份资料，执行前重新核对实际清单，不把历史记录中的四页数量写死。沿用已有主题和稳定 `page_id`，核对 `expected_version`，复用原件身份、字节版本、有效解析稿、出处及手动分类；重新提交正文与每页摘要，发布新的内容版本。保留旧发布、任务和来源历史。不存在批内派生依赖时同批更新；存在依赖时按拓扑逐批整理，每批对应独立受信任务，下游引用刚发布的上游版本，沿用原 `page_id` 和当前指针版本作为 `expected_version`，不绕过同批依赖校验。每次发布失败保留该次发布前仍有效的旧页；上游已成功更新导致下游暂停时，沿用失效规则并继续处理下游，不承诺跨批次全库原子切换。成功后每个主题只有一个当前有效版本，旧版仅供追溯。已有视觉缺口如实保留，不为补摘要强制重复全量视觉处理。
- **恢复与验收**：真实重整前停机完整备份，记录原件哈希、当前页身份／版本、分类、出处、关系与视觉范围；实现验证通过后经已有重新整理入口使用现有配置执行，复用同一请求标识处理网络重试。失败或取消不删除仍有效的旧知识；已提交的候选优先恢复，不重复生成。跨批次失败继续重整已暂停下游；必要的整体回退使用备份恢复到新空根及对应源码版本，保留较新现场，不把合并恢复当作撤销。完成后核对摘要与正文、目录／搜索／提示词、全部出处、重启及异根备份恢复；来源失效或版本冲突按原契约拒绝迟到发布。真实模型结果与离线替身分别记录。

### 5.8 文档读取与知识入库优化（2026-11-11 方案，PA-15）

本节为新增行为的唯一正文；[专项方案](../../docs/codex/plans/2026-11-11-文档读取与知识入库优化方案.md)维护实施安排，[工单 16](issues/16-document-reading.md)为领取入口。依据为[真实 PDF 对比](../../docs/codex/logs/2026-11-11-PDF读取方案对比.md)及 [OpenAI 文件输入说明](https://developers.openai.com/api/docs/guides/file-inputs)。本节替代第 5.3／5.5 节中默认逐页视觉的处理方式，保留其原件、出处、用途、有效性与可检索规则。

**RD-01 范围与责任。** 首批优化 PDF、DOCX、PPTX，保留 XLSX、MD/TXT；DOC/PPT 仅在经验证的本地转换器可用时支持，不能改后缀后按 OOXML 解析。XLS 及宏格式不扩为本次承诺。程序准备材料、管理预算与证据，主 Agent 阅读并整理主题知识；不增设逐页模型先转述、主模型再理解的必经步骤。一般阅读与知识入库共用文件准备及传输能力；一般阅读不因此自动建立长期知识，入库仍须受控登记和第 6 节用途判断。

**RD-02 各格式路线及定位。**

| 格式 | 默认准备与阅读 | 权威出处与缺口 |
| --- | --- | --- |
| PDF | 本地提取可获得的文字和页结构；接口能力已验证且预算允许时，将任务需要的原件或选定页 PDF 直接交主模型，文字提取不触发全页渲染／OCR。 | 原件物理页；拆分文件保存“批内页→原件页”映射。扫描页、矢量图与混合页走相同原生入口；局部读不清时另行渲染。 |
| DOCX | 保留段落、表格、图片／图表锚点等结构，生成本地排版 PDF 阅读副本并交主模型；结构文字供定位与检索，不强制重复全量塞进上下文。 | 原件章节／段落／表格／对象位置与对应阅读副本页，可一对多。无法证明对应关系时只引用明确标为“阅读副本”的页，不伪造 Word 原始固定页码。 |
| PPTX | 保留幻灯片结构、对象、备注与隐藏标记，生成静态 PDF 阅读副本，按幻灯片或多页批次交主模型。 | 原件幻灯片序号及稳定页标识／对象位置；阅读副本页另行映射。知识整理默认覆盖隐藏页并保留标记，备注作为单独文字层提供，不能只导出可见页后称全部已读。 |
| DOC／PPT | 仅通过已验证的本地转换器读取隔离副本，之后走上述路线。 | 保留原件与转换身份；转换失败或不可用时说明缺少能力，不返回假成功。 |
| XLSX | 沿用单元格／区域、公式与缓存值，按任务提供可提取的嵌入图片；图表保留结构／已有缓存及视觉缺口，本次不承诺完整图表渲染。 | 工作表、单元格／对象锚点；图片缺锚点则明确缺口。图表缓存不等于已验证计算，不默认把整工作簿打印成 PDF，不以接口前 1,000 行增强代替全表读取，不重算公式或执行外链／宏。 |
| MD／TXT | 沿用文字、章节、行号及分页读取。 | 保留现有引用；不为纯文字增加图文转换。 |

Office 直接上传的官方预处理仅提取文字，不能据此保证内嵌图表已进入模型。Word 的正文按最终显示视图读取，保留页眉页脚、脚注／尾注及现有域显示值；修订、批注单独登记为附加层，不当作当前正文事实。PPT 静态画面、备注、隐藏页分别记录；动画时序、视频、音频及无法呈现的嵌入对象列为未处理层，不宣称静态 PDF 已保留这些内容。用户要求分析附加层时将其纳入本次读取目标，能力不足明确返回缺口。

转换只操作本任务隔离副本；记录原件与副本哈希、转换器及版本、字体／版式警告、转换选项和位置映射。禁止执行宏、刷新外链或为转换重算表格／更新动态域，不改原文件及用户全局设置。转换器不能证明这些约束时，对应格式保持未就绪。超时只结束本任务创建的转换进程，不连接或关闭用户正在编辑的 Office。缺转换器时可继续可靠的结构文字与独立图片读取，受影响图文范围标为不完整；不临时启用新的云端转换商。

**RD-03 能力、外发与预算。** 原生附件按 Provider、模型、协议、媒体类型和配置修订分别记录 `supported / unsupported / unknown`；PDF 内嵌数据、Files 上传、文件 ID 和 URL 是独立能力。当前 MUZE 的 Responses 内嵌 PDF 有实测依据，Files 路径未通过，不硬编码域名或假定所有中转都兼容。未知能力先做小型无敏感内容探针；不支持则复用已有视觉／文字回退，不静默切换未配置的服务商。任务所需全文整理可在既有授权范围内发送本任务整份资料；只问局部则发送局部，不因登记资料而发送整个历史库。此处将 ADR-0001 的必要内容落实到任务范围，不新增默认云端归档或向量化。

每次发送同时检查原始字节、base64 后请求体、页／对象数量、预计上下文、输出及时间预算，预留系统提示和整理输出空间。能整份处理时整份；超预算时按章节、幻灯片组或页区间拆成多个 PDF，保存映射。公式、表格及上下文跨边界时保留必要邻接页；邻接页重叠不重复生成知识。上下文实际超限时缩小原生批次，不先退回全书逐页 OCR。上传连接超时与等待模型响应的超时分别设置，不能把 TLS／限流／超时误记为永久不支持附件。自动重试必须有上限，结果未知不承诺模型侧恰好计费一次。

**RD-04 主模型媒体交付。** 原件及副本由程序生成有作用域的媒体引用，绑定当前用户、会话／任务、attempt、配置修订及资料版本。真实文件／图像内容块须进入主 Agent 的实际模型请求；工具回执保留文本提示和非敏感阅读标识，不能将 base64、文件路径或 file 字典 JSON 化后当作已提供媒体。私有路径、密钥及大段编码不进入普通日志、摘要、系统索引或持久聊天正文。历史压缩保留引用和阅读结果，需要再次看原文时重新校验再展开；后续每轮不能自动重复发送整本附件。普通文件只读沿用现有路径权限和运行身份，媒体能力不扩大访问范围；需要写入知识时先完成受控原件登记。

旧 `read` 的文字返回、`offset/limit` 与明确指定的旧 `parse_id` 保留原义；显示续读不改变原 ordinal，不偷偷发起新的全量识别。显式 `visual=false` 禁止新增视觉／附件模型调用，可返回已有文字和缓存结果。新增自动路线在未禁止媒体调用且权限／预算允许时优先原生；不支持媒体的协议明确回退。图文交付不能依赖把工具结果假装成新的用户授权。

**RD-05 阅读证据与覆盖。** 程序为一次逻辑阅读生成不透明 `reading_id`，持久保存版本化阅读记录（v1）和不可变材料清单：原件／副本身份、哈希、解析与转换版本、批次及源位置映射、任务身份、配置修订、实际调用结果及未覆盖原因。准备成功、已发送、请求完成、模型提取的具体观察分别登记；“请求完成”仅证明该批材料已进入一次成功响应，不证明每个图文细节均被正确理解。未发送、取消、结果未知、超预算及模型明确读不清的部分不能被改记为已完整处理。

新工具回执以可选 `reading_id`、批次／覆盖信息和续读定位扩展，不把新增字段设为旧客户端必填。来源输入支持两种明确互斥的形状：既有 `document_id/revision_id/parse_id/ordinal`；或 `reading_id/evidence_key`，后者引用同一提交的 `reading_evidence`。使用新形状时须提供非空 `reading_submission_id`，网络／工具重放沿用该标识；每项新证据包含 `reading_id`、`evidence_key`、程序提供的 `segment_id`、范围内的页／原件 `location`、非空具体 `observation` 和 `type`（图中文字转写或视觉解释）。不接受模型提交的另一 owner、原件路径、来源哈希、状态快照或任意 parse_id 来建立可信身份。

证据别名的作用域为受信 owner、持久任务身份、`reading_submission_id`、`reading_id`、`evidence_key`；普通会话的入库先由受控综合入口登记任务。同一提交允许多个 reading 各用同名 evidence_key；同一 reading 内键必须唯一。比较工具校验后的完整载荷（segment、位置、观察与类型及程序绑定的材料身份），对象键顺序与证据数组顺序不影响相等判断；不把不同观察或位置归并。同键同载荷复用同一四元出处，同键异载荷在新增副作用前返回 `idempotency_conflict`。别名映射一旦持久保存不可重排；观察已保存但候选未保存时中断，重试仍复用原映射与 ordinal，并发重放也只生成一次。

程序核对媒体确实来自该任务的成功阅读回执、原件仍有效、位置在已提供范围内，再将观察作为模型产物保存为不可变解析单元，解析版本由真实载荷计算。由程序将别名解析成既有四元出处后进入 Wiki 发布；不能把“已读取该文件”占位文本当作证据，也不要求为此再转写每一页。图中文字转写与视觉解释都保留模型来源和具体位置，不冒充原件文字层；可用的原文摘录另用已登记文本单元。程序校验身份、版本和位置，不宣称机械校验已证明语义无误。相同阅读成品重放复用其证据与候选，不重复追加单元。

新解析稿保留原有单元及 ordinal，新增观察只追加到新的不可变解析版本；不得原地改写旧 parse。原生来源、转换结果和观察仍可经原件／阅读副本回查；读取该出处不能只返回知识页自述。分开保存文字提取、媒体提供、语义缺口及整理覆盖，不能将“没有全量 OCR”判成原生路线失败，也不能将“PDF 上传完成”判成全书理解完毕。

**RD-06 从阅读到知识。** 新收录默认整理本次指定资料范围；主 Agent 基于已提供材料直接提交主题标题、分类、正文块、出处、相关关系及第 5.7 节每页摘要。程序只保存验证后的阅读证据与候选，随后沿用第 5.4／5.5 节原子发布和索引核验；不先生成一份整书逐页 OCR 摘要再强制调用主模型重复总结。跨批次先记录各批发现和未处理范围，最终按主题合并，而非一页原件机械生成一页知识。已成功发布的知识及有效观察可复用，只有缺口或版本／目标变化才补读。

执行前持久保存本任务目标范围、必需阅读／整理批次及对应原件版本，模型不能通过少交出处缩小目标；范围调整使用受信任务动作或新任务并保留原目标历史。每个发布批次发起前登记幂等提交身份，记录对应范围和发布结果；批次提交与整任务完成分别判定。尚有目标未完成时保持 running 并继续，不因发现一个发布记录就调用任务 complete；单轮预算不足保留游标，达到任务执行上限则 failed、stage=parse、错误 `reading_incomplete`，保留候选及已发布 result_refs。重启先按各批提交身份核对实际发布，补齐缺失的批次回执，再继续剩余目标；只有整个任务目标满足后提交 succeeded/outcome=published。

明确的语义缺口不阻止无关且有依据的主题发布，资料显示尚待补读范围；要求完整覆盖而未达到的任务仍为未完成／失败，已发布部分可查询。取消与整任务最终完成的提交屏障决定胜者；部分批次发布后仍可取消剩余工作，已提交发布保留，迟到结果不得新增发布，撤回仍走独立来源动作。跨独立拓扑任务沿用第 5.7 节：各任务只判定自身目标，上游成功不能代表下游或全库完成，不用本节批次台账合并为跨任务原子发布。上游更新后继续处理已暂停下游，不复活旧知识。

**RD-07 持久化、恢复与兼容。** task schema v1 的既有状态、outcome 和阶段保持，阅读子记录／附加表独立带版本；缺失表示旧路径，不反推旧任务已具备原生阅读。缺少／非法新证据或未知子记录版本在副作用前拒绝；未知格式不按空数据覆盖。原生能力、材料准备、模型响应、观察／候选、发布和回执分别存检查点；原件及衍生文件以稳定相对身份恢复，不能依赖旧数据根的绝对路径。

续处理复核 task/attempt、原件与副本哈希、配置及来源状态。旧 attempt 尚未提交或迟到的模型回调一律拒绝；已在有效提交屏障内持久保存的响应／观察／候选，由受信恢复器重新核验后建立“当前 attempt 接续原产物”的关联才可复用，原产生 attempt 和记录不改写。不能让模型自行宣称某旧回执已经接续。已取消任务不自动恢复执行；重新处理按既有入口创建新任务。

有已保存且仍有效的响应／候选则复用，不重复付费生成。只有请求已发、结果未落盘的窗口可能需要再次调用，记录结果未知与重试次数。进行中任务不借用新配置；原配置不可用沿用已有 config_unavailable 与按当前配置重新处理入口。缓存以逻辑资料版本、材料／映射哈希、转换器、解析与模型配置、发送范围和目标关联；相同字节但不同资料身份不得混用权威来源。跨任务复用合格缓存必须在新任务建立自己的 reading_id 和受信复用关联，保留原产物身份及配置；不能直接冒用原任务的阅读授权。换模型／处理配置不兼容时只复用仍兼容的材料，不将旧模型响应伪装为新模型结果。备份纳入阅读记录、材料、观察及映射；丢失可重建副本只使依赖它的证据待恢复，不把已知失效内容恢复为有效。

旧发布和旧候选沿用原解析语义，新记录不批量重写旧来源或摘要。普通旧客户端可以继续显示文字／状态；不理解新媒体证据的后端不能写入启用新记录的数据根。降版沿用第 8 节“保存最新全量快照、旧版仅打开兼容恢复点”，禁止用旧代码重解释新证据后继续发布。新错误至少区分 `attachment_unsupported`、`conversion_unavailable`、`conversion_failed`、`reading_incomplete` 与既有的配置／限额／存储／版本错误，均可追踪原因、阶段和可否重试。

**RD-08 交付与可观察结果。** 文件已保存、阅读中／待补读、知识已发布及索引可用分别显示；资料范围、页码／幻灯片和转换缺口可查。沿用资料与知识界面，不新增逐页审批流程，解释放问号悬停，主界面保留必要状态。实施后按格式分别以真实主 Agent 从文件阅读到知识整理、关键词检索、回读出处验收：某格式通过共用证据／恢复要求及自身链路后即可启用，不等其他格式的转换器就绪；首批全格式交付仍须 PDF、DOCX、PPTX 分别通过。真实 PDF 回归复用既有 23 点题集，但不能把先前问答结果当成新入库链路验收。增加 Office 特有问题及中文样本，记录首次处理与缓存复用的调用、时延、tokens、观察／知识质量和剩余缺口，不预先承诺普遍 5 倍提速。

### 5.9 知识检索与使用体验优化（2026-11-11 方案，PA-16）

2026-11-12 修订：当前交付主线不要求向量模型，按 KR-08 优化已有词项检索、证据融合、导航及恢复，可独立完成并验收。KR-02～04 的向量启用／缓存／代际，以及其余规则中的向量分支延期为可选后续；不是当前工单完成条件。本节同时保留第 7 节 PA-12 的后续启用契约，未来另行执行并验收后才超出第 5.5 节“首期仅关键词”阶段。本轮交付方案，不重整资料、不改变数据目录。执行入口为[工单 17](issues/17-knowledge-retrieval.md)，唯一执行安排为[专项方案](../../docs/codex/plans/2026-11-11-知识库检索与使用体验优化方案.md)。

**KR-01 权威与检索对象。** 原件、被引用的不可变解析稿、发布记录和版本正文共同保留证据；当前发布指针、用途、来源有效性与依赖仍由现有权威登记决定。关键词和向量均先定位主题页及正文块，再回读正文和原件回答；索引摘要、扩展术语和向量不单独成为事实。只扫描当前有效托管知识，历史页、临时来源和完整会话不自动向量化。普通 Markdown 和尚有效且未退役的旧 managed 继续沿原规则检索，不强制迁移。

**KR-02 显式启用与发送范围（后续可选）。** 后续新增可选布尔配置 `knowledge_semantic_enabled`，缺省 false；非法类型在配置保存时拒绝，手动配置文件中的非法值按禁用处理并诊断。仅当 knowledge 开启、embedding_enabled 未关闭且本开关为布尔 true 时尝试托管知识向量。复用独立 Embedding 配置，要求明确 Provider 绑定与解析后的模型，不借用会话供应商或自动发现其他密钥；旧安装普通 memory 的缺省行为不受本开关改变。启用意味着把有效主题的标题、摘要、正文块以及查询文字交给所选 Embedding 服务；不附带原件、解析全文、历史、会话或出处元数据。发送前核对来源、用途和当前发布。配置未齐或不可用时保持关键词并显示原因，本轮不选择服务商、不发送资料。候选重排首期不增加远端服务，保留现有已配置重排的发送边界。

**KR-03 缓存与可检索状态（向量部分后续可选）。** 向量按 Agent／workspace、索引代际、page_id、page_version、正文块及必要子块标识存储，附正文／输入哈希和出处关联所需身份；出处从权威记录回建。缓存位于消费方 Agent 根的 memory/long-term 独立知识检索缓存区，不改现有 index.db 的通用向量空间。运行期绑定实际解析出的权威来源根；切换自有／共享来源时立即使旧活动指针未就绪。持久清单保存规范排序的资料／发布身份、正文哈希和来源状态快照摘要；绝对路径、目录同名及页标题不作为可迁移库身份。换根或恢复后逐项比对实际权威记录，再复用匹配缓存；无法匹配的库隔离重建，不新增一套可写知识身份权威。发布仍以关键词索引核验及有效指针提交为成功条件，提交后后台增量生成向量，失败不回滚已发布知识；启动对账补齐缺项，不重整知识、不改原件和解析 ID。标题、摘要或正文改变才更新对应输入；只改分类不重复 Embedding。被引用解析稿缺失时报告待恢复，不能换解析器重跑并冒充原证据。

**KR-04 代际与配置切换（后续可选）。** 指纹沿用第 7 节，覆盖 Provider ID、规范化端点、实际模型／维度、向量格式和输入／分块版本；查询缓存也包含完整指纹。密钥轮换不要求重建向量，但请求授权和 config_revision 必须重新核对；同维换模型必须新建代际。构建在已绑定配置修订下执行，有持久检查点；旧修订不可用时停止该 attempt，显式重建可复用相同指纹的已校验产物。新代际先构建、校验并追补期间提交的有效页，切换前重核发布清单，再原子切换活动指针；来源提交与缓存无跨库事务，查询始终另核权威状态。切换后新页的暂时缺项由关键词补足。每次查询先遵守原任务 config_revision（无任务的即时查询在入口捕获修订），固定该修订选定的 Provider／模型指纹与匹配代际，不跨代融合查询向量和文档向量。旧代际仅供绑定修订仍明确选择该向量空间、凭据可用且仍获授权的查询使用；新修订选择 B 时不能借保留的 A 代际调用 A，旧修订选择 A 也不能查询 B。没有匹配代际则关键词降级；若原任务修订按第 7 节已不可执行，仍返回 config_unavailable，不以关键词绕过任务阻止。构建失败、关闭或回退不删除原件、证据和当前可用代际。

**KR-05 融合与失效屏障。** 向量存储／召回按 page_version＋block_ordinal＋subchunk_ordinal 区分；正文块融合按 page_version＋block_ordinal 归并，标题／摘要选页提示单独按 page_version＋page 标识；命中范围及定位精度见 KR-08。向量通道先对同一正文块取最高子块相似度生成块级排名，同时保留所有命中子块位置，再与关键词整块融合。禁止用固定 path／1～1 行去重而吞掉同页不同块，也不以块编号伪造真实行号。相同块的多通道命中去重并保留全部实际引用位置。保留搜索结果原 start_line/end_line 字段，由已核验的不可变 Markdown 和正文块结构计算真实行区间；无法唯一定位的旧格式返回整页真实行范围并标明页级定位，不能伪装精确块位置。原件出处仍使用 source_reference 中的真实位置，工具显示及按返回行号回读必须一致。各检索器先内部排序，再按排名融合不同来源／通道，不直接相加余弦、关键词次数及 FTS 分值；保留普通 memory 的单通道与阈值语义，同分稳定排序。术语匹配可辅助找页，不能新增未经证实的正文。同页展示可归组，但回答所需多块、多来源证据不能被折叠丢失。缓存命中转为证据、已授权远端处理前、最终返回及回答回读时均核对当前指针、哈希、来源和依赖；撤回先提交权威状态，缓存可随后清理。耗时调用期间失效的候选被丢弃，迟到索引不能恢复发布；一致性以最后权威核验为准，后续回答仍刷新引用状态。

**KR-06 导航与兼容接口。** 复用已有当前目录、摘要、手动分类、只读历史和资料管理。日常打开状态按 Agent 作用域＋page_id 解析当前版本，历史入口按明确发布版本固定正文；当前页暂停时显示状态，不自动退回旧版。旧路径、中文链接和锚点继续可定位其原版本。首次进入优先当前有效目录，整理记录、历史与兼容文件区按需进入；无托管知识时保留普通 Markdown 入口。当前目录不增加必填配置或“待配置向量模型”提示；状态可仅报告关键词可用，不能因未部署语义能力显示故障。后续现有 catalog 可附加 `retrieval` 对象：mode 为 keyword/hybrid，semantic_state 为 disabled/building/ready/degraded，indexed_units/pending_units 为非负整数，reason 为可选错误码；旧接口字段不改义，旧服务缺对象视为状态未知。ready 仅表示当前有效集合已核对覆盖；新增页或配置变化即时刷新状态。界面仅显示必要状态，说明放问号；不把现有目录文字筛选宣称为语义搜索。

**KR-07 重建、故障与恢复。** 目录投影、权威关键词索引、向量缓存分别对待：新向量重建不调用会先清空通用索引的旧命令，不顺带修写 wiki_units 或发布状态。缺失／损坏向量、查询超时或无权使用旧 Provider 时降级关键词，显示真实模式；无依据时报告未找到支持，不猜出处。完整备份沿用停机及 SQLite 一致快照，覆盖既有证据与配置；恢复至新根后核验现有当前／历史关系；保留缓存也须重新绑定实际权威库并校验清单才可 ready，绝对路径变化不触发原件或出处改写。向量缓存可丢弃重建且不改引用身份。未知缓存版本可隔离重建；未知权威 schema 仍按既有契约停止写入。关闭新开关可回退，旧程序的降版仍使用匹配恢复点，不让缓存可丢弃变成忽略权威数据兼容的理由。

**KR-08 当前无向量主线。** 知识词项分支不初始化 Embedding／额外重排模型，不新增服务和向量持久化；沿现有发布记录查询，不以“有待构建语义索引”阻止关键词发布与回答。零模型调用约束针对新增词项分支：统一 memory_search 中原已配置的普通 memory 向量／重排行为保持，不静默关闭，也不计作新增分支的请求。无向量整链验收显式使用 embedding_enabled=false、rerank_provider 为空；另测旧字段缺省的既有自动选择、已有向量／重排配置，均只允许原有调用，不因词项增强额外初始化或请求模型。Agent 问答仍使用当前会话模型及既有任务配置。

- **词项与排名**：一次本地词项查询同时匹配标题、版本摘要及正文，仅对查询／索引副本规范化大小写、全半角及常见分隔形式。保留 VNA、RF、S11／S21 等短技术词及完整词组，英文按词项边界匹配，原文和位置不变。别名仅采用有效资料明示或用户提供的对应关系，不把相关词当作等价词。完整词组／原词优先，再按覆盖度与字段生成稳定排名，权重由固定开发集调节；普通 memory 的阈值和返回格式保持。
- **提示、证据与定位**：新增结果字段 match_scope 可选且仅取 page/block；普通 memory 或旧记录缺省时保持旧处理，不据缺省补造托管出处；新托管结果出现非法枚举时丢弃该候选并诊断。标题／摘要独有命中为 page 提示，身份为 page_version＋page，只携带页身份、真实路径／全页行范围和选页文字，不填块序号、已选原文出处或 source_reference。正文命中为 block，身份为 page_version＋block_ordinal，携带经核验的真实块与出处；同页已有 block 时合并 page 的排名线索，不另占一个结果位，也不把摘要当正文。同页多个不同块继续保留。另以 line_precision=exact/page 表示 Markdown 定位精度，与命中范围独立；正文命中但旧格式仅能定位整页时仍为 block，保留真实块身份及出处，line_precision=page。工具对 page 始终输出“选页提示，须回读”；先回读正文再选证据，摘要不与任意原文块绑定。
- **计数与停止**：三次预算仅作用于个人助手模式中一次顶层 Agent 执行轮次的知识检索，不作为整个会话或跨重启的终身上限。受信运行入口创建轮次身份；同轮工具调用及子代理继承同一原子计数器，模型不能通过工具参数重置。通常一次，必要时追加两次；每次通过参数校验并进入检索执行即计一次，空结果、执行失败及重复调用也计入，参数校验失败和正文／原件 read 不计。第四次调用在检索前返回 retrieval_budget_exhausted，不再请求检索器或模型，提示回读已有候选或说明缺口，不表示全库没有知识。同轮暂停／恢复不清零；新用户执行、显式重试的新 attempt 或进程重启后新建轮次才重置，不持久承诺跨轮总次数。没有 Agent 轮次的直接旧 API／普通 memory 调用保持单次原行为，不自动扩展查询。新增预算不改既有任务终态、配置修订或全局 agent_max_steps。
- **回答与阶段边界**：本地词项分支不外发；原有已配置远端能力仍遵守原配置范围。每个候选、回读和回答继续核对有效性／用途／出处；任意同义改写不承诺等同向量召回。当前指标与未来语义指标分别按专项方案第 5 节验收。

## 6. 自主判断、留档与引用（PA-07、PA-09、PA-13）

已确认原始记录完整保留、首期不自动删除。知识整理沿用[现有系统提示](../../agent/prompt/builder.py#L654)和 [knowledge-wiki](../../skills/knowledge-wiki/SKILL.md)：用户分享资料、讨论产生有价值结论时，主 Agent 主动提炼并写入知识，不例行询问“要不要收录”。知识功能启用、索引初始化及技能加载是否实际生效，由实施验证。

| 判断 | 行为 |
| --- | --- |
| 分享资料或产生可复用知识 | 主 Agent 按内容、对话和现有知识自主提炼、分类并调用收录工具，留下简短理由与真实结果；无需固定口令或逐份确认。 |
| 用户指定或上下文明确只供临时任务使用 | 原始会话、附件与处理轨迹留档；不发布为长期知识，也不经日记摘要、Deep Dream 等路径变为长期记忆。 |
| 缺少会影响处理结果的必要信息 | 例如不能确定要替代哪个版本、指令互相冲突时，先保存接收记录与原件，再询问具体问题；相关候选暂不发布。 |

用途判断交给主 Agent，程序负责执行、权限、来源版本和发布回执，不新增硬编码的资料分类审批表。模型判断出错时，用户可以更正用途或撤回。D-03 按用户既有自主判断要求及本轮补充意见关闭，不再作为实施前待确认项。

原始历史留档、长期知识发布、个人偏好记忆是不同用途。临时来源的内容及派生结论需要携带用途标记，摘要输入和各写入入口共同遵守排除规则；用户后续明确转为长期资料时再建立发布记录。

对新回答的引用须关联 document_id、revision_id、parse_id 和原文定位。检索后回读原文，并核对版本仍有效；不是只给出一个知识页链接。

- 替代：默认召回当前有效版本；历史版本明确查询时可看，显示已替代状态。
- 更正：登记更正依据和影响的结论／知识页；立即阻止已知失效内容作为当前结论，新投影完成后再发布。
- 撤回：先提交不可召回标记，再清理／重建派生索引与缓存。默认不物理删除完整留档；永久删除属于另行明确的动作。
- 旧聊天答案不被静默重写。打开其引用时仍可定位原件，并显示当前已更正、已替代或已撤回；已撤回来源不能作为后续答案的当前证据。
- 关键词、向量、检索缓存、知识页直读及模型重新使用上下文都核验有效状态；故障或索引滞后时先过滤失效版本。已加载旧上下文的后续推理须刷新受影响证据。
- 云端推理按任务读取必要内容，保留与 ADR 一致的发送范围。全量留档不自动变成全量 prompt、全量上传或自动向量化；原件正文不进入普通错误日志。

## 7. Provider 与配置切换

模型连接及能力选择复用已有厂商目录、模型目录、能力卡和兼容／原生协议实现。

| 初始用途 | 地址 | 模型 |
| --- | --- | --- |
| 会话 | https://api.muzeai.top/v1 | gpt-6.1-sol |
| 绘图 | https://image.aikun.uk/v1 | gpt-image-2.5-flare、gpt-image-2.5-sunburst |
| Embedding / ASR / TTS | 各自后续配置 | 各自后续配置 |

这些是可编辑初值，不是硬编码路由，也未验证用户服务可用性。绘图两个模型均可登记，当前选择只绑定一个；默认及备用在启用时选定。

实施契约：

- 同地址不同密钥可有独立 Provider ID；不同能力显式绑定 provider_id 和 model。缺少必要配置显示未就绪；只自动回退到该能力已配置的备用列表，不能借用会话密钥尝试其他能力。
- 配置沿用已存在字段与模型能力标签；新增版本号为附加元数据。缺省读旧字段，保存时保留无关字段及掩码密钥语义；非法绑定／删除仍被引用的 Provider 应报错并给出引用位置，不能静默改到另一供应商。
- 保存成功需原子持久化，相关客户端缓存失效。保存后的新任务使用新 config_revision；已运行任务及其重试使用原修订。若原凭据已无法重建，停止该 attempt 并说明重新提交方式，不静默切到新端点。
- 业务任务在接收提交时绑定整套能力选择的 config_revision；已排队但未运行、重启恢复的任务也沿用该修订。保存配置不修改已接收任务的绑定；需要改用新连接时取消原任务并显式重新提交。task 不保存密钥正文，无法取得原修订可用凭据时显示配置不可用，不自动改路由。
- 已因配置不可用而失败的普通附件任务，可由本机用户显式选择“按当前配置重新处理”：核验并复用原件创建新任务，沿用原会话与身份并登记父任务；原失败记录保持，候选、用途决定与发布结果不复制。来源状态动作任务不走此入口；同一提交标识幂等，普通重试继续沿用旧配置。
- 进行中的回复、文件与通知始终归属原 owner、task 与来源会话。新客户端不得接收上个配置修订的迟到缓存结果。
- 请求、错误和配置回执不回显密钥。实际使用的 provider/model/config_revision 可查。
- 首期关键词模式须是显式可验证的配置；不能以 embedding_provider 为空来表示关闭，因为现有空值会自动尝试旧 OpenAI/LinkAI 路径。需要时增加向后兼容的启用开关，默认不改变旧安装的行为。
- 启用 Embedding 前定义索引指纹：Provider ID、服务地址、模型、维度、向量格式及解析/分块版本；密钥变化本身不代表向量空间变化。
- 换会话模型不重建知识向量。Embedding 指纹不兼容时新建索引代际、完整校验后切换；维度相同不代表模型兼容。失败时保留旧代际，仅在旧 Provider 可用且仍获配置授权时查询旧向量，否则退回关键词并显示状态。
- 不兼容代际不混搜；原件与出处引用保持连续。原件、权威登记不因向量重建失败而删除。

Embedding 迁移属于后续启用前的受影响重大契约。首期即使未做全量向量切换，也必须能验证没有意外向量请求。

## 8. 兼容、失败与桌面交付（PA-01、PA-11）

### 8.1 兼容策略

| 对象 | 实施规则 |
| --- | --- |
| 官方程序与数据 | 定制版独立应用标识、数据根与工作空间；不自动扫描、搬迁或接管官方目录。当前无旧数据迁移工作。 |
| 已有配置/API | 增加字段／入口保持兼容；旧接口对未托管资料行为不变。旧导入返回仍表示旧含义，新任务入口明确 accepted 与 published 的区别；不偷偷更改旧字段含义。 |
| 未托管 MD/TXT | 继续读写及原检索能力；未登记来源时保留“来源未登记”的事实。升级不猜测其原件或清空其索引。 |
| 新增权威记录 | schema_version=1；未知大版本只读诊断或停止该功能，禁止降版覆盖。需要改版时在副本先迁移，记录来源版本与回退点。 |
| 备份恢复 | 覆盖完整会话正文、附件及其会话关联、处理轨迹、原件、来源版本登记、发布指针、任务、通知记录及所需配置；索引可重建。SQLite 使用一致快照，不仅复制主文件而遗漏 WAL 中的提交。 |
| Windows 打包 | PyInstaller 后端先构建，包含解析依赖与数据文件，再构建 Electron/NSIS；dist:win 不替代后端构建。 |
| 更新与回退 | 定制版不无条件跟随官方自动更新；降版前保留最新完整快照，旧程序只使用匹配版本的数据快照或明确只读诊断，不让旧写入器打开未知格式数据。界面记录恢复点时间；较新留档继续保留，供回升后恢复，不承诺旧程序读懂新版记录。 |

安装验收使用独立空目录；卸载／升级不默认删除个人原件、留档和知识。具体应用名、目录名是可配置实现选择，无需作为新的用户审批。

### 8.2 故障后应看到什么

| 失败点 | 数据／回执与恢复 |
| --- | --- |
| 接收记录提交前失败 | 不报告已接收；由渠道重投或用户重发，不能承诺离线期间必达。 |
| 原件下载或保存中断 | 已有 receipt/task 可查，原件不标完成；临时块与最终原件区分，重试后核验哈希。 |
| 解析失败／超限 | 原件与错误完整留档；不发布不完整知识，修复或选择新解析能力后重试。 |
| 判断过程失败 | 原件已保存、用途未定；任务可重试或等待补充，不假定已长期收录。 |
| 索引失败 | pending_index；旧有效发布不变，结果显示“已保存，待索引”，单独重试索引。 |
| 发布时修订冲突 | 旧指针不变，候选留档，返回 version_conflict 并核对当前版本。 |
| 发布提交后进程退出 | 启动按发布提交标识恢复成功结果，不二次发布；通知单独恢复。 |
| 取消与完成竞态 | 按提交顺序决定已完成或已取消；已取消 attempt 的迟到结果仅留处理记录。 |
| 通知失败／未知 | 业务结果保留可查询；已知失败可重试，未知先核对，不重做业务。 |
| 配置保存失败／切换失败 | 已保存的上一配置仍可用，失败明确；不得返回假成功或用半套新旧连接。 |
| 向量重建失败 | 旧索引代际与原件保留，显示失败／降级；不发布混合代际。 |
| 备份不完整／恢复版本不符 | 停止恢复并保留目标已有数据，不能部分覆盖后宣称恢复成功。 |

## 10. 决策状态与技术前置

- **D-01 已解决**：原始会话、附件与处理记录完整保留，首期不自动清理；取代此前“七天清理”的建议。
- **D-02 已解决**：定制版独立目录，从空目录开始；当前不建设历史数据迁移。
- **D-03 已解决**：沿用软件与模型现有的自主知识整理能力，用户分享资料后主动处理；遵守明确的临时用途，仅在缺少必要信息时具体澄清。此前将此原则重复列为待确认项，现已纠正，不阻塞 T-04。
- 首批三格式按 PDF/DOCX/XLSX 实施；若用户代表样本必须依赖旧格式、OCR 或公式重算，先更新该范围，不把不完整文本算作验收通过。
- 服务商端点能力、本机运行链路、解析预算、安装数据路径与索引兼容由计划中的隔离探针验证，未知项只阻塞依赖它们的任务。Embedding/语音/绘图供应商未选齐不阻塞文本知识闭环。
