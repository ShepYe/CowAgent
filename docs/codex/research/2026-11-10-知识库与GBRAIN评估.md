## 结论与取舍

**针对个人知识沉淀，建议先保留 CowAgent 的 `knowledge/` 为唯一知识正文真源，继续使用已有 memory 检索；本轮不引入 GBrain。** 现有实现已覆盖收录、索引、交叉链接、关键词/可选向量检索、按行读取、修改后重建索引与基础冲突检测。GBrain 最有价值的增量是多个 Agent 共用的结构化事实、来源与时效、更正/撤回、实体关系和持久写入回执；这些增量需要第二套数据库、服务生命周期与备份体系。[本地源码：knowledge 服务](D:/CodeAndDesign/CowAgent/agent/knowledge/service.py)、[memory 管理器](D:/CodeAndDesign/CowAgent/agent/memory/manager.py)、[GBrain 记忆协议][G5]、[数据真源契约][G6]。

**GBrain的引入条件应是已被真实任务证明的知识层增量：结构化来源/时效/更正治理、实体关系检索、独立知识生命周期等；多个工具共享只是可能的使用方式。** 首版明确不接入，后续评估条件见[起步路线](2026-11-10-起步技术路线建议.md)。若以后接入，同一知识域只能选一个正文写入者。这个结论是架构建议，不是性能实测结果。

硬件条件由主代理提供：Windows 11 中文家庭版、Core Ultra 5 125H、23.5 GiB RAM、可见 Intel Arc 集成显卡；本调研未复测硬件，没有 CUDA 独显证据。建议优先本地文件与关键词检索；若试用外部知识服务，先使用远端模型或现有模型接口、限制并发，不同时叠加完整 RAGFlow 和本地大模型。后述资源判断均为建议或官方要求，不是本机容量测试。

### Windows：已修复的路径问题与仍需验证的边界

1. **已查源码：GBRAIN_HOME 已使用 `path.isAbsolute()`，不再只接受 `/` 开头。** `GBRAIN_HOME` 是父目录，程序再追加 `.gbrain`；并检查 `..` 路径段。不要把它设置为预期的最终 `.gbrain` 目录后再误认为不会追加。[config.ts][G8] 历史问题 #1019 已关闭，并记录过 Windows 驱动器路径拒绝问题；旧 issue 不能当作当前版本仍完全不可用的证据。[官方 issue](https://github.com/garrytan/gbrain/issues/1019)。
2. **已查源码：Windows 写文件名约束仍真实存在。** 页面持久化路径会检查 Windows 冒号目标，并在绑定目录的文件写穿路径上拒绝；数据库独有写入和文件写入的限制不同。[page-mutations.ts][G9] 因此不能假设任意跨平台 slug 都能无损变成本地文件名。
3. **已查源码：安装后脚本针对 Windows PATH 做过处理。** `scripts/postinstall.ts` 使用 Bun 的 Windows-aware `which` 及参数数组启动方式，说明存在 Windows 适配，不等于全流程已验证。[postinstall 源码](https://github.com/garrytan/gbrain/blob/a0af9b6689cd78520dda7132d34a93c95333f2f5/scripts/postinstall.ts)。
4. **官方文档：服务托管主要覆盖 macOS 的 launchd 和 Linux 的 systemd。** 远程 expose 路径还可能写 wrapper、设置 Tailscale、配置长期服务；没有在本次已查文档中确认等价的 Windows 服务托管。[远程 MCP][G10] 建议若以后试验，先做前台进程/stdio，或单独评估 WSL/Linux 服务端；WSL 是备选部署建议，不是本机已满足条件。
5. **官方贡献文档：bash 与换行符有约束。** `.gitattributes` 固定 shell/Markdown 为 LF；文档说明 CRLF 可能影响 frontmatter 读取。[贡献文档](https://github.com/garrytan/gbrain/blob/master/CONTRIBUTING.md)。该文档为滚动页面，曾写 Bun 1.4.0；本次固定 commit 的 `package.json` 已要求 1.4.4，采用源码门槛。

### 推荐归属：先坚持一个写入体系

**当前方案（建议，不实施）**：

- `memory/` 保存用户偏好、近期决策与对话记忆；`knowledge/` 保存有来源、可反复编辑的个人知识与综合结论。检索可共用，不因检索共用就复制正文。
- `knowledge/index.md` 和 `log.md` 继续由 CowAgent wiki 流程维护；SQLite/向量索引作为派生物。知识备份以正文和来源材料为核心，索引可重建不等于其他会话数据都可丢弃。
- 不将 GBrain 的事实表、frontmatter/fenced facts/takes 格式直接混进现有 wiki 并允许双向写入。原子文件写入只能保护单次发布，不能解决两个系统的语义覆盖、日志顺序与索引失配。

**若以后引入 GBrain（建议）**：选择独立 GBrain 内容根，由 GBrain mutation API/MCP 唯一维护那部分正文与事实；CowAgent 保留自己的运行记忆/指令，针对共享知识做读取或显式写入调用。原 CowAgent wiki 先保持只读归档或做有记录的单向迁移；不要双向同步。另一种选择是 CowAgent 仍为唯一文件作者、GBrain 仅作单向派生索引，但必须禁用会回写这些文件的 capture/remember/synthesis/maintenance 路径并验证模式，复杂度可能抵消收益。[真源与发布主机契约][G6]、[记忆边界][G7]

## 最小可落地方案与后续验证门槛

以下只定义后续工作，不在本轮创建知识页、改配置或启动服务。

1. **先建小而完整的个人知识闭环**：选 20–50 份真实资料，沿用 `knowledge/<category>/<slug>.md`、index 与 log。每页至少记录原始 URL/本地原件路径、检索日期、文档或软件版本、事实与个人判断、待确认项；原始材料和模型综合分开保留。无需先上实体图谱。
2. **定义更正规则**：同一主题更新现有页；明确哪些结论失效、替代关系、来源与生效日期。两个官方来源冲突时保留冲突，不让检索相似度决定谁是真相。现在先做文档规约，不声称 CowAgent 已有结构化 supersession ledger。
3. **查询回读正文**：memory_search 负责找候选，memory_get/read 负责回读，最终回答链接到实际文件与对应来源。向量相似度、重排分数都不能代替证据。
4. **做固定小样本评估后再加服务**：人工准备至少 30 个问题，包括中文精确查找、同义表达、跨页综合、旧事实更正、删除、无答案。记录是否找到证据、引用是否支持结论、旧内容是否仍召回，以及耗时/索引成本。建议验收：事实性断言均能回到证据，无答案和冲突问题能明确说明；修改/删除在显式同步后不再命中旧段落。阈值是建议，不是当前达成结果。
5. **Windows 后续试验清单**：在独立测试目录中验证中文/空格路径、文件名约束、stdio 启停、PGLite 单进程锁、多客户端行为、修改后检索、断电/进程重启、撤回与备份恢复；每项记录 tag、Bun 版本和模型配置。完成这些才可称可用，不以 doctor 通过或 tools/list 可见替代。

引入门槛按实际缺口决定：持续需要多个 Agent 共用来源事实与撤回记录 → GBrain；大量 PDF/扫描件解析与管理成为瓶颈 → 文档平台；固定跨实体问题在页面检索中持续失败且有评测收益 → 图谱 RAG；向量规模/并发在测量中成为瓶颈 → 外部向量库。单纯资料数量增加不自动触发迁移。

## 其他知识层候选（简评）

这三项按能力层选取，不按星数排序；它们都不直接替代个人知识的正文归属规则。

| 候选 | 真正的层级与已核实接口 | 真源、更新/引用、图谱和导出边界 | Windows/资源与取舍 |
|---|---|---|---|
| RAGFlow | 文档摄取/知识库/RAG 平台。官方 REST 包含文档、chunk、retrieval；1.0 内建 Go MCP endpoint，支持 Streamable HTTP。[HTTP API][R2]、[MCP][R3] | API 有 document download、chunk update 和引用返回；这些不等于全库一键可移植导出或事实矛盾消解。README 声称可生成 wiki/graph 等知识产物，质量未实测。[README][R1]、[HTTP API][R2] | 当前官方建议起步 4 核、16 GB RAM、50 GB 空间、Docker≥24/Compose≥2.26.1；1.0 DeepDoc 使用 CPU 推理。23.5 GiB 是整机内存，不是容器独享，叠加本地模型余量不足以默认保证流畅。优先远端服务或独立机器，仅在复杂文档需求突出时考虑。[部署要求][R1] |
| LightRAG | 图谱增强 RAG 框架/服务，支持 local/global/hybrid/naive/mix 等查询；query API 可返回 references，含源 file_path。[query 源码][L2] | 文档/切块/向量/关系存于工作目录或配置后端，不是 Markdown 即全部真源。默认可用 JsonKV/NanoVectorDB/NetworkX；有实体/关系编辑，需与导入图一致性一起管理。[核心文档][L1]、[graph API][L3]。源码 `export_data/aexport_data` 导出实体与关系，可选向量，格式 csv/excel/md/txt；不能当作所有原文与缓存的完整恢复包。[核心源码][L4] | README 有 Windows 环境说明；启用内嵌 SVG 光栅化还可能依赖系统 libcairo。模型抽取、embedding 和关系重建有成本；本机不默认跑本地大模型。内建 MCP 在本轮未确认，API 接入明确。[README][L0] |
| Qdrant | 向量/检索存储层，有 REST/gRPC、混合 query；官方另有 MCP server。[quickstart][Q1]、[hybrid query][Q2]、[MCP 仓库][Q3] | points/payload 由应用决定内容、来源和版本；upsert 不是事实冲突消解。scroll 可导出指定 payload/vector，snapshot 可备份 collection；需要另存知识正文和引用语义。[upsert][Q4]、[scroll][Q5]、[snapshot][Q6]。本轮没有确认它提供 GBrain 式知识事实图，不以向量邻接代替知识图。 | 官方 Docker quickstart 提醒 Windows 可能需要 named volume。资源随向量维度、数量、索引/副本增长，没有本机容量结论；仅在现有向量后端瓶颈被量化后考虑。[quickstart][Q1] |

区别：记忆负责“应持续记住什么、何时更正/忘记”；个人知识库负责“原始资料与整理结论如何可读、可引用、可维护”；RAG 框架负责“检索与生成流程”；向量库负责“向量/元数据存储与查询”。GBrain 横跨前两项并带 RAG 能力；不能把任一框架/数据库的存在当作个人知识治理已完成。

## 未知项与研究限制

- 未实测 GBrain/CowAgent 联调、本机性能、中文检索质量、模型费用、导出恢复及权限隔离；没有安装或运行仓库脚本。源码检查不是验收。
- 未确认 GBrain 原生 Windows 的完整 CI/二进制支持矩阵、所有传递依赖许可证与锁文件重现结果、可选模型供应商对 Intel Arc 的支持。依赖清单来自声明，未做供应链审计。
- 没有本机空闲内存、磁盘余量、Docker/WSL 配置证据；本轮不推断 Windows 家庭版已满足某一 Docker 后端要求。
- 官网页面可能滚动变化；固定 commit 源码与检索当日 release 分开记录。GBrain 文档存在 runtime floor、工具注册默认 surface 的不同描述，已经在相关位置列明。
- 前期广义检索曾返回社区帖子和镜像；没有将二手内容用于技术结论。用户确认身份后停止歧义检索。
