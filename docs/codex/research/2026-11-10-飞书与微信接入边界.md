# 飞书完整业务操控与微信专用助手接入边界

调研日期：**2026-11-10，Asia/Shanghai**。范围：飞书业务执行为重点；微信仅需与专门助手机器人聊天、下达任务和接收结果，不要求个人历史会话、联系人、朋友圈操控。

## 1. 当前判断与推荐路径

1. **建议：飞书采用“机器人消息入口／长连接 + CLI 业务工具 + 必要时 OpenAPI／SDK”组合。** 用户指定的官方概述明确分成凭据层（一键建应用）、交互层（Channel SDK）和执行层（CLI）；机器人能收消息不等于能操作文档、日历或审批。[指定概述原页](https://open.feishu.cn/document/mcp_open_tools/overview-of-lark-agent-integration-capabilities)、[本次实际读到的官方 Markdown 正文](https://open.feishu.cn/document/mcp_open_tools/overview-of-lark-agent-integration-capabilities.md)。
2. **官方宣称：远程 MCP 当前主要覆盖云文档；个人托管 MCP Token 链路将逐步下线，官方推荐 CLI。** 因此不把远程 MCP 选作完整业务底座；开源 OpenAPI MCP 是另一条产品线，也不能与远程 MCP 混称。[远程 MCP 工具清单](https://open.feishu.cn/document/mcp_open_tools/supported-tools.md)、[个人使用 MCP 服务及下线提示](https://open.feishu.cn/document/mcp_open_tools/end-user-call-remote-mcp-server.md)。
3. **已查官方源码／文档：个人微信已有腾讯官方专用 Bot 路径。** `Tencent/openclaw-weixin` 提供扫码绑定、长轮询收消息、发送回复；源码声明 `chatTypes: ["direct"]`，符合本需求的专用助手单聊入口。不能继续使用“个人微信没有官方机器人”的旧结论。[腾讯官方仓库说明](https://github.com/Tencent/openclaw-weixin/blob/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e/README.zh_CN.md)、[渠道源码](https://github.com/Tencent/openclaw-weixin/blob/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e/src/channel.ts)。
4. **未确认：个人微信 Bot 的精确主动推送窗口、context_token TTL 和配额。** 已读官方协议建议回传入站 `context_token`，发送实现缺 token 时仍尝试请求；这不能证明服务端接受，也不能证明永久有效。CowAgent 中“24h 窗口”的注释只能作为其实现假设，不能升级为腾讯官方规则。[官方协议](https://github.com/Tencent/openclaw-weixin/blob/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e/docs/protocol_zh_CN.md)、[发送源码](https://github.com/Tencent/openclaw-weixin/blob/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e/src/messaging/send.ts)。
5. **建议：个人微信入口优先验证官方 Bot；接受使用企业微信客户端时，以企微专用智能机器人作为另一条路径。** 企微当前长连接协议明确支持定时提醒和异步任务通知，但主动推送的到期条件与较早腾讯产品指南存在表述差异，见第 6 节；不能承诺无人互动时永久推送。[企微长连接协议](https://developer.work.weixin.qq.com/document/path/101463)、[腾讯产品接入指南](https://intl.cloud.tencent.com/zh/document/product/1316/84454)。

## 4. 飞书身份、权限和业务覆盖

### 4.1 tenant 与 user：谁在操作，能看到什么

- **官方宣称：tenant_access_token 代表应用，绝不是“租户超级管理员通行证”。** 云文档应用有独立云空间；访问非自有文档需所有者向应用授权，知识库需管理员授权。应用云空间不能直接由 UI 管理。**user_access_token 代表授权用户**，访问他人资源仍需该用户已有资源授权。[云文档业务模型与接入流程](https://open.feishu.cn/document/server-docs/docs/docs-overview.md)。
- **官方宣称：CLI 中 bot scope 在开发者后台开通；user 则要后台 scope 与用户授权同时满足。** CLI 身份选择存在 auto；建议生产工具显式选 user 或 bot，不能遇到空结果／权限失败就静默换身份。[CLI 身份参考](https://github.com/larksuite/cli/blob/1bfdcc2c1a0ed0296ddb6349d251bdd75145bc5a/skills/lark-shared/references/lark-shared-identity-and-permissions.md)。
- **官方宣称：用户授权还涉及续期。** CLI 参考说明若没有取得 refresh_token，约两小时后不能自动续期，需管理员开启刷新 user_access_token 并发布后重新授权。具体以返回的有效期和授权状态为准，不能只存 access token 就承诺长期后台运行。[续期参考](https://github.com/larksuite/cli/blob/1bfdcc2c1a0ed0296ddb6349d251bdd75145bc5a/skills/lark-shared/references/lark-shared-identity-and-permissions.md)。
- **建议：实际可执行范围按“接口支持的身份 ∩ 应用 scope／发布配置 ∩ 用户授权（如适用）∩ 对象 ACL／角色 ∩ 租户策略／功能可用性”检查。** 机器人可用范围、通讯录范围、文档协作者、审批操作者不能用一个“已授权”统称。[发消息权限和范围](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/create.md)、[云文档授权](https://open.feishu.cn/document/server-docs/docs/docs-overview.md)、[审批任务接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/approval-v4/task/approve.md)。

### 4.3 长连接、后台任务和异步飞书通知

**官方宣称**：飞书 SDK 的长连接由服务主动出网建立 WebSocket，不需要公网入站域名；仅支持企业自建应用。事件处理需在 3 秒内完成，否则会重推；每应用最多 50 连接，多客户端为随机一个接收的集群模式，不广播。[长连接事件文档](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)。

**建议**：事件到达后快速持久化、去重并入队，模型／业务长任务异步处理；不要在事件处理函数里等待几十分钟。聊天入口和业务执行凭证分开配置。最终结果通过消息 API 发送，并遵守可用范围、入群发言及限流条件；本次已读发送 API 没有列出微信式 24／48 小时对话窗口，但不能据此声称无限消息额度。[发送消息 API](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/create.md)。

### 6.1 企业微信推送时间窗口：明确差异，不强行合并

**当前协议已读**：[智能机器人长连接](https://developer.work.weixin.qq.com/document/path/101463) 对普通 `aibot_respond_msg` 写明“收到消息回调后，24 小时内可以往该会话回复消息”；流式消息从开始发送起须在 **10 分钟内**完成。回复和主动推送共用同一会话 **30 条／分钟、1000 条／小时**限额。

**当前协议已读**：`aibot_send_msg` 支持无当前消息回调触发的定时提醒、异步结果和告警；须先有用户在该会话向机器人发送过消息。主动推送段落没有明确写“首次互动后永久有效”，也没有单独重述 24 小时到期条件。因此只能确认支持主动推送，**不能确认其超过 24 小时仍然可发**。媒体推送能力也应按相应消息类型和接口单验。[同一协议主动推送章节](https://developer.work.weixin.qq.com/document/path/101463)。

**较早腾讯产品指南的不同表述**：2026-09-30 的 CodeBuddy 接入指南写流式 6 分钟、5 分钟回退，以及 `aibot_send_msg` 24 小时有效期；它是该产品集成说明，不能覆盖当前企业微信协议中的 10 分钟规则，也不能据此把主动推送窗口争议写成已解决。[腾讯产品指南](https://intl.cloud.tencent.com/zh/document/product/1316/84454)。

**建议**：普通回复按 24 小时上界设计，流式与长任务分离；对主动推送做 24 小时前后、重启和再次互动对照实测，必要时请求腾讯确认当前服务端规则。5 秒要求在当前协议的欢迎语、卡片事件中有明确用途，不把产品指南的表述推广为所有普通消息均须在 5 秒内完成模型推理。

## 8. 推荐落地顺序与待账户实测验收

### 8.1 推荐路径（建议，本次不实施）

1. **飞书主执行层**：将官方 CLI 作为覆盖评估入口，固定 `1.0.99` 对照版本；个人业务显式 user、机器人资源显式 bot。关键或缺失动作再用官方 SDK／OpenAPI 补齐。审批单独确认实际 endpoint 与操作者，不能统一替换 token。
2. **飞书交互层**：沿用 CowAgent 现有长连接接任务；是否迁移 Channel SDK 是工程选择，不是扩展业务权限的前提。任务先入队，结果持久化，再按飞书消息 API 通知。
3. **个人微信入口**：以腾讯官方个人 Bot 路径做最小闭环，验证 CowAgent iLink 适配与最新 PIN／实名流程是否兼容；保持微信身份与飞书授权用户的明确绑定，微信发来指令本身不授予任何飞书业务权限。
4. **企微替代入口**：接受企微客户端时使用专用 API 智能机器人长连接；若要求超过一天无人互动仍必达，需要单独验收主动推送或企业内部应用消息路线，不能靠客服窗口兜底。
5. **共同可靠性**：任务创建、业务执行、结果落盘、通知发送分别记录状态；通知失败不丢结果，跨渠道回传遵守用户授权的数据范围。高影响写操作按用户业务规则确认，不以机器人已接通作为验收。
