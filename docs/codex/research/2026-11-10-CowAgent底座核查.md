## 1. 核心判断

**[判断] 可作为 Windows 本机个人助手的交互、通道、工具与基础 Agent 运行底座；对“跨重启可靠任务执行”和“GBRAIN 独占知识写入”必须另定边界。** 已有模型—工具循环、MCP、skills、Markdown 记忆/知识、检索、任务持久化、桌面后端监护，无须先重写这些基础层；但当前持久化更接近“留住历史与调度配置”，尚不能据此验收为可恢复的业务工作流。依据见下列逐项源码，尤其第 4–7 节。

**[建议] 初期保留 CowAgent 主循环；GBRAIN 若负责长期知识，应成为该知识域唯一写入者。** CowAgent 的 MEMORY.md、日记摘要、Deep Dream、knowledge-wiki 和自进化都可能改写持久文件；只接一个检索 MCP，并不会消除这些写入路径。必须关闭或隔离重复写入，再通过一个知识写入 API/MCP 向 GBRAIN 提交材料；不要让双方后台整理同一批 Markdown。具体映射见第 5 节。

### 5.2 建议的单一写入安排

**[建议] 先明确 GBRAIN 是否同时拥有“用户长期偏好记忆”和“主题知识”。** 两者均归它时，执行下表；若只拥有主题知识，可保留独立的 CowAgent MEMORY.md/日记，但必须禁止两边同步维护相同事实，明确冲突时谁权威。此为架构约束，尚未实现。

| 数据域 | 建议权威写入者 | CowAgent 侧需要约束的入口 |
| --- | --- | --- |
| 对话、工具轨迹、调度运行记录 | CowAgent | 保留 SQLite 与步骤记录；这些是运行证据，不让 GBRAIN反写聊天历史。 |
| 长期事实、偏好、主题知识（若全部交给 GBRAIN） | GBRAIN | 停止同域自动摘要/Deep Dream；停用或改写 knowledge-wiki 的本地写入指引；停用或限缩 self-evolution 的同域写入。 |
| 知识页面、索引、关系图 | GBRAIN | CowAgent KnowledgeService 的 Web 创建/更新/导入入口也须禁止写同域，不能仅隐藏菜单；模型 write/edit/bash/MCP 不得绕行直写知识根。 |
| 检索缓存、展示投影 | 适配层从 GBRAIN 单向生成 | 标明非权威且可重建，按版本刷新；禁止反向双向同步和独立 Deep Dream 重写投影。 |
| skills 与运行配置 | 用户审批的独立维护域 | 可保留 CowAgent 技能体系，知识写入只经 GBRAIN API；不把技能自修改与知识事实更新混在一起。 |

约束依据是上一节所列实际写入路径。**[判断] 仅靠提示词无法强制单一写入权**：全权限命令和文件工具可写盘；需要在知识目录/服务接口处落实访问控制。普通 workspace-write 也允许工作区内的文件修改，不能充当“GBRAIN 才能写”的规则。参见第 7 节权限源码。
