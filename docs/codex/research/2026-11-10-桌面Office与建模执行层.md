# Windows 本机助手：Office、PDF 与射频箱体建模执行层

调研日期：2026-11-10（Asia/Shanghai）。范围：执行工具选型、原生应用与文件处理边界、Windows 会话与电源状态、工程制造交付。本文为专项调研，不展开 RFLink 业务和上层编排设计。

证据类型：官方文档、项目官方源码、项目发布者维护的 PyPI 元数据。文中“建议／推断”是基于这些证据的工程判断，不是厂商承诺。**未安装、启动、运行或连接 Office、LibreOffice、Blender、FreeCAD 及 MCP 服务，未进行转换、重算、UIA 或加工验证；未修改业务、系统设置或提交 Git。**

## 3. Office 文件库与原生执行的分工

### 3.1 文件库：直接操作文档结构

| 工具 | 足够适用的任务 | 能力边界与选择建议 |
| --- | --- | --- |
| python-docx | DOCX 的段落、样式、表格、图片、节和页眉页脚；基于模板生成报告 | 官方定位是创建、更新 DOCX。本文将其作为文件结构层，不把写入分页符或域代码当成已完成 Word 分页／域求值；分页和最终 PDF 交给目标渲染器。[官方文档][docx] |
| openpyxl | XLSX 单元格、样式、公式字符串及常见表格数据；读写宏文件时按选项保留 VBA | **不求值公式**；`data_only=True` 读取已存缓存，不能证明结果新鲜；`keep_vba` 是保留而非编辑／运行 VBA。官方提醒未覆盖所有 Excel 元素，重新保存可能丢失 shapes。复杂原有工作簿优先原生修改或在副本验证。[公式][xlsx-formula]、[读写限制][xlsx-tutorial] |
| python-pptx | PPTX 占位符、文字、图片、形状、表格与支持的图表；模板化批量生成 | 无需安装 PowerPoint，但公开 API 未覆盖完整格式。官方声称能 round-trip 保留各元素，不等于各元素都有编辑 API，更不等于有 PowerPoint 渲染引擎；复杂动画、SmartArt 等任务应逐项核查，不能统一宣称全部支持或全部丢失。[官方能力说明][pptx] |

**建议**：文件库任务输出可编辑源文件，并记录使用的模板、字体和库版本；不能以“文件可保存”验收公式正确或版面正确。文件结构、计算结果和渲染结果分别验收，原因是上述库的结构处理能力与原生应用计算／导出能力分属不同接口。[openpyxl][xlsx-formula]、[Word 导出][word-pdf]、[PowerPoint 导出][ppt-pdf]

### 3.2 COM／live automation：实际调用 Office

- **Excel**：`Application.CalculateFullRebuild` 对所有打开工作簿进行完整计算并重建依赖；`CalculationState` 可查询计算状态。建议用助手独占的实例处理副本，等待计算完成再保存并读回结果；外链、异步刷新、加载项／自定义函数是否就绪另行验收，不能把“计算结束”解释为所有外部数据都已更新。[完整重算][excel-calc]、[计算状态][excel-state]
- **Word**：`Document.Repaginate` 执行重新分页；`Fields.Update` 更新该集合的域，官方示例针对正文 main story；不能据此声称一次调用覆盖所有页眉页脚等 story。建议按文档结构更新相应域／目录，再分页、保存、导出。[分页][word-pages]、[域更新][word-fields]、[PDF 导出][word-pdf]
- **PowerPoint**：`Presentation.ExportAsFixedFormat` 使用原生固定版式导出，官方明确对应 UI 的 PDF／XPS 操作，结果是演示文稿的静态视图；它不保留可播放动画语义。[官方 API][ppt-pdf]

“live”应表示连接实际运行的应用对象／会话，并说明控制的是用户现有文档还是助手实例。原生应用可获得自身的计算和排版行为，但字体嵌入／替代等条件仍影响输出，不能承诺任何电脑逐像素一致；Word 导出参数已明确体现字体许可与替代行为。[Word 导出参数][word-pdf]

**运行建议**：同一 Office 实例串行执行，对连接到用户实例的工作不调用全局退出，不覆盖用户未保存内容；保存到新路径并读回验证。微软说明 Office 是非重入、STA 应用，存在全局资源共享，多个实例并发也不是天然隔离；这些建议来自此运行模型。[Office 无人值守限制][office-rpa]

### 3.3 LibreOffice headless：有引擎的替代方案

LibreOffice 在 Windows 提供 `soffice.com` 命令行入口，支持 `--headless`、`--convert-to`、`--outdir` 与 `-env:UserInstallation=...`。它启动自己的转换引擎；“无头”表示无 UI 运行，不表示不运行软件。建议独立 profile、隔离输出目录，并检查输出文件与内容，而不只看进程退出。[官方参数][lo-cli]

Calc 的 UNO `XCalculatable.calculateAll()` 明确重算所有单元格。因此它可补足 openpyxl 不求值的缺口；仅凭一次 `--convert-to` 命令不能证明已按预期完整重算。建议在需要确定重算的路径显式调用 calculateAll，再保存／导出并比对预期值。[UNO][lo-calc]、[Calc 重算][lo-recalc]

官方支持 Word／Excel／PowerPoint 格式的打开与保存，并说明 Office VBA 与 LibreOffice 对象模型不通用。由此作出的选型判断是：它适合独立的兼容转换路径，不能承诺 Excel 公式／宏／加载项语义或 Word／PowerPoint 排版完全一致；关键模板、分页、图表、中文字体和打印区域需做样本验收。[官方兼容说明][lo-ms]

| 工具 | 推荐职责 | 明确边界 |
| --- | --- | --- |
| pypdf | 拆分、合并、裁剪／变换、元数据、加解密、表单字段、合并水印层 | 不是 OCR；PDF 原始结构未必提供段落／表格等语义，不能当作 Word 正文编辑器；不承担页面像素渲染。[项目文档][pypdf]、[提取说明][pdf-text] |

**建议的输出路线**：需要原生 Office 版面的 PDF，由 Office 输出；可接受兼容版面的批处理由 LibreOffice 输出；完全由数据定义的标签／报告由 ReportLab 输出；最终再用 PDF 工具拆合、盖章、渲染验收。脱敏应检查输出中的可提取内容，不能把白色覆盖矩形视为内容已删除。[Word PDF][word-pdf]、[LibreOffice 参数][lo-cli]、[ReportLab][reportlab]、[PyMuPDF 脱敏][mupdf-page]

## 5. Windows 登录、锁屏、注销与休眠

### 5.1 状态矩阵

以下为依据微软机制形成的执行策略；“可运行”均以机器处于工作状态、进程存在、账户权限及网络有效为前提，**不是本机验证结果**。

| 系统／会话状态 | 消息接收、文件库、HTTP／API 等后台任务 | Office COM／live | 桌面 UIA／鼠标键盘 |
| --- | --- | --- | --- |
| 已登录、已解锁、系统保持工作 | 用户进程或独立服务可承担；前台窗口不是文件／API 任务的必要条件 | 最合适的本机使用环境，仍可能被许可提示、弹窗或文档状态阻塞 | 优先 UIA pattern，缺口才使用前台输入；需要目标权限和控件支持 |
| 已登录但锁屏，尚未睡眠 | 锁屏不等于注销；已有后台工作可继续，但不能把锁屏等同于永远保持工作状态 | 部分无需交互的对象模型调用可能继续；**不能承诺完整流程在锁屏下成功**，遇到 UI 依赖应等待解锁 | 微软文档说明部分 pattern 操作适合 locked session；输入注入不可用，截图可能需要可用交互桌面 |
| 已注销／开机尚无人登录 | 只有按服务或适当非交互任务身份启动的工作才有运行基础；用户登录启动的助手不能据此承诺在线 | 服务／SYSTEM／非交互任务中运行 Office 落入微软不建议、不支持的配置；不作为默认通路 | 不存在该用户的可交互桌面；服务不能直接操作用户 UI |
| S3 睡眠／S4 休眠 | 不承诺持续执行、实时接收或按时轮询；恢复后需重连、补拉与恢复队列 | 不执行持续自动化承诺，恢复后检查应用与文件状态 | 不可持续交互，恢复后重新确认会话与目标 |
| Modern Standby（S0 低功耗待机） | 不等于普通 S0 持续运行；桌面应用会被暂停，第三方服务也受到执行限制 | 不承诺持续运行 | 不承诺持续交互 |

矩阵依据：[服务与交互会话][services]、[任务登录类型][task-logon]、[UIA 锁屏操作边界][winapp-uia]、[Office 无人值守限制][office-rpa]、[系统电源状态][power]、[Modern Standby 应用执行][standby]。

### 5.2 四个不能混同的边界

1. **后台进程与交互桌面不是一件事。** 微软建议服务通过 IPC 与用户会话中的独立 GUI 进程通信，服务自 Windows Vista 起不能直接与用户交互。建议常驻消息／文件／API 核心与用户会话执行器分离；锁屏时后台核心可处理可独立完成的任务，UI 依赖任务等待会话恢复。[微软服务文档][services]
2. **“无需登录即可运行任务”不等于“有桌面／网络凭据”。** `TASK_LOGON_INTERACTIVE_TOKEN` 要求用户已登录，S4U 则在非交互桌面执行且不能访问网络或加密文件。因此不能把任意计划任务身份直接用于后台收消息／网络盘／API；须分别核对运行身份和认证方式。[微软任务登录枚举][task-logon]
3. **不能写成“锁屏后 UIA 一律失效”，也不能写成“UIA 都能锁屏运行”。** 微软 2026-11-07 更新的 winapp UIA 文档将 `invoke`／`set-value` 等 pattern 操作与 OS 输入注入分开；后者要求解锁且目标在前台，截图另有交互桌面依赖。这是该官方工具的能力说明，不是所有第三方 UIA 包或 Office 控件的统一保证。普通 UIA 也不能突破更高完整性级别和安全桌面限制。[官方操作说明][winapp-uia]、[UIA 安全边界][uia-security]
4. **原生 Office 可以自动化，不代表适合做无人值守服务。** 微软提供 Microsoft 365 Apps 无人值守 RPA 的许可路径，同时明确无用户运行是 AS IS，非交互客户端／服务中的 Office 自动化不建议、不支持，可能阻塞或死锁。把 `Visible=False`、购买 RPA 许可或 App Paths 注册当作可稳定后台运行的证明，均缺乏依据。[RPA 许可][office-license]、[运行限制][office-rpa]

**建议**：产品状态至少分开报告 `background_ready`、`interactive_ready`、`waiting_for_unlock`、`suspended_or_offline`。这只是执行层状态建议；不要求修改本机设置、自动解锁或改变休眠策略。若要求电脑睡眠期间仍实时响应，应另设始终在线的消息入口与持久队列；本机恢复后补拉，不能依赖“后台常驻”四字作保证。[电源状态][power]、[Modern Standby][standby]

## 6. Blender 执行方式与 blender-mcp 边界

### 6.1 优先使用官方 bpy／命令行

Blender 官方命令行源码支持 `--background`、`--python`、`--python-expr`、`--python-exit-code`，并明确参数按给定顺序执行。建议用固定脚本读取结构化尺寸参数，在独立 Blender 进程中生成／保存场景、导出资产和渲染；以 Python 异常退出码、输出存在及几何检查共同验收，不能只等渲染窗口结束。[官方命令行源码][blender-cli]

bpy 的数据 API 与 `bpy.ops` 不应混为一谈：operators 依赖当前 area、选择和活动对象等 context，`poll()` 可失败。建议 background 建模优先数据 API，确需 operator 时逐项验证 context；不能假定交互界面里可用的每个操作都能在无头环境照搬。[官方 API 限制源码][blender-ops]

官方还支持将 Blender 构建为可 `import bpy` 的 Python 模块；该交付方式与普通 Blender 安装不同，官方普通下载页不直接提供这一模块形态。建议首选固定版本 Blender 可执行文件，只有确有嵌入需求时才评估单独 bpy 包／构建与 Python ABI、依赖版本，不把任意系统 Python 中的 `import bpy` 当作既有能力。[官方 bpy 模块说明源码][blender-module]

### 6.2 blender-mcp 是第三方集成，不是 Blender 官方执行接口

截至本次核对，`ahujasid/blender-mcp` 的项目元数据声明名称为 `mcp-for-blender`、版本 `2.2.7`、MIT，并明确不隶属 Blender Foundation。本文按仓库标识与固定提交识别项目，不把市场上的其他同名 MCP 视为同一实现，也不对维护质量或后续持续维护作承诺。[固定提交元数据][mcp-meta]

其结构为 MCP Server 连接 Blender 内 addon 的 TCP socket；固定源码的默认监听是 `localhost:9876`，非 loopback 绑定需额外选择。addon 的 `execute_code` 最终调用 `exec(code, namespace)`，因此它提供的是 Blender 进程权限下的任意 Python 执行能力，不能按“只会改模型”的权限理解。[addon 源码][mcp-addon]、[server 源码][mcp-server]

项目 README 明示 socket 无认证、无加密，能到达该端口者能在 Blender 中运行 Python。MCP Server 侧提供默认关闭的 `BLENDER_MCP_SAFE_MODE` 并在代码工具入口检查脚本；这不等于 addon socket 自身具有独立认证，也不足以证明形成操作系统沙箱。[README][mcp-readme]、[代码工具入口][mcp-server]

**建议**：确定性的箱体／丝印批处理使用固定版本脚本和命名操作，不开放任意代码为日常接口；只有需要观察和迭代当前场景时才选 MCP。若以后采用 MCP，应固定提交，复核实际入口、代码执行、监听地址、外部资产服务及遥测设置，并在受限账户／进程环境中运行。此为由源码权限边界推导的设计建议，本文没有连接端口、运行 safe mode 或测试漏洞。[源码][mcp-addon]、[项目说明][mcp-readme]

## 7. 射频箱体、丝印：可视化与可制造交付

### 7.1 工程尺寸和约束必须是显式输入

**建议建立单一参数表**，至少包含：单位（如 mm）、外廓长宽高、壁／底／盖板厚、基准面及原点、腔体布局、连接器孔坐标与方向、螺钉／沉孔／螺纹规格、安装柱、倒角圆角、密封／导电接触面、避让范围、材料与表面处理。未知尺寸、公差与加工参数保留“待确认”，不由模型自由猜测；具体数值由结构要求与加工方确认。选择参数化 CAD 的证据是 FreeCAD 的模型历史参数机制与 Sketcher 的几何／尺寸约束求解能力。[FreeCAD 官方说明][freecad]、[Sketcher][fc-sketch]

推荐约束包括对称、同心、孔距、边距、平行／垂直及装配间隙；改外廓尺寸时需重新检查孔、柱、腔壁和盖板配合。Sketcher 官方区分自由度、几何约束和尺寸约束，完全约束表示草图自由度被约束，不自动证明尺寸正确或可加工。[官方约束说明][fc-sketch]

Blender 适合依据同一参数表生成箱体外观、透明／剖切视图、装配表现和丝印预览；bpy 生成的数值几何可以用于可视化检查，但本文没有证据可将 Blender 的一般网格建模流程认证为带工程约束和公差的制造主模型。建议制造主模型由 CAD 维护，再派生 Blender 预览，避免分别手调两套尺寸。[Blender 执行接口][blender-cli]、[FreeCAD 参数化能力][freecad]、[工程出图][fc-drawing]

### 7.2 FreeCAD／STEP／加工图

FreeCAD 官方格式表列出 STEP 的导入和导出，Part Export 支持 STEP／IGES／BREP；TechDraw 可从三维模型生成视图、剖面、尺寸与注释，并输出 SVG／DXF／PDF。因此在本范围内，它是比纯表现建模更贴近加工交付的候选执行层。[格式表][fc-formats]、[Part Export][fc-export]、[TechDraw][fc-drawing]

**建议交付包分开保存**：

| 交付物 | 用途与验收建议 | 依据 |
| --- | --- | --- |
| FCStd 与参数表／生成脚本 | 保留设计历史、命名尺寸及约束；改尺寸后可重新生成 | [参数化机制][freecad]、[Sketcher][fc-sketch] |
| STEP | 实体交换；回读核对单位、总体尺寸、实体数量、孔位和有效性。不要承诺接收方可恢复原始草图／特征树，本文只核实普通几何交换能力 | [STEP 格式能力][fc-formats]、[Part Export][fc-export] |
| 加工 PDF／必要的 DXF | 三视图、剖视／细节、基准、公差、孔／螺纹、材料、表面处理和版本；按供应商要求明确尺寸与工艺 | [TechDraw 出图能力][fc-drawing]；交付内容为本文工程建议 |
| Blender 场景／渲染图 | 视觉审阅和沟通，标注对应 CAD／参数版本；不能替代实体与尺寸图 | [Blender][blender-cli]、[CAD 出图][fc-drawing]；用途分工为本文建议 |

STL 等网格与 STEP 的工程模型交换在官方格式表中分别列出；不能把网格封闭、导出成功、渲染无穿帮等同于加工图齐全。本文也未核实任何网格转 STEP 插件是否能恢复解析曲面或设计约束，不能据此承诺“Blender 一键制造交付”。[官方格式表][fc-formats]

### 7.3 丝印需要平面生产母版

**建议**：丝印用与 CAD 面一致的二维坐标系生成 SVG／矢量 PDF，逐面定义原点、正反面、朝向、1:1 实际尺寸、定位标记、文字与端口对应关系、颜色／层以及文字轮廓／字体交付规则。最小字高、线宽、距孔／边界距离、套印误差等数值交加工方确认，不写未经依据的通用阈值。ReportLab 可用于生成尺寸明确的 PDF 页面，TechDraw 支持矢量出图，但具体丝印工艺验收仍需另行完成。[ReportLab][reportlab]、[TechDraw][fc-drawing]

Blender 材质贴图／浮雕文字可检查视觉方向和装配效果；透视渲染不能作为 1:1 丝印定位母版。建议从同一二维几何派生生产文件和 Blender 展示，防止文字、孔位和镜像方向分叉。这是交付设计建议，不是对某个 Blender 丝印插件的能力认证。[Blender 脚本能力][blender-cli]、[矢量页面生成][reportlab]

**射频边界**：本文只选型几何建模与文档执行层，没有核实电磁求解、屏蔽效能、谐振、热／强度、接地接触或实物测试工具链。箱体与丝印外观完成不能作为射频性能或制造放行结论；这些验收应独立于本专项。

## 9. 以后验证的最小集合（本次均未执行）

1. 在用户已登录并解锁的会话，核对 Office 版本／激活；用副本验证 Excel 公式重算、Word 分页／域及 PowerPoint PDF 输出，并保留原生与输出文件。

4. 用已确认的参数构建简单箱体，改关键尺寸后检查约束和几何，再将 STEP 回读；加工图和 1:1 丝印母版分别经加工方确认。
5. 若后续选择 blender-mcp，再审计固定版本监听／代码执行／safe mode／外部连接与数据收集行为；本次源码阅读不代替部署验收。
