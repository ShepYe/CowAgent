## 整份文件与传输验证

- **12 页规格书**：一次原生请求成功，117.268 秒，输入 36,982、输出 4,891 tokens。回答整理了规格、版本及配件边界并给出页码。抽查第 9 页 9 项关键数值与封面 7 项标识/粗略位置均符合原图；没有逐项核验所有输出。其输出明显长于 6 页问答，不能直接按页数比较耗时。
- **68 页手册**：原件 11,071,892 字节，内嵌后的请求约 14.76 MB。首次在较短上传连接超时下发生 TLS 写入异常，没有收到服务端响应；将测试上传连接超时从 20 秒放宽到 90 秒后成功，总计 89.036 秒。输入 185,518、输出 697 tokens，正确找到第 30 页流程图与第 53 页连接器图；附加参数出处 8、10、11 页经文字回读核对。重试耗时不包含第一次失败的 23.770 秒。
- **独立 Files 上传**：按标准 multipart `purpose=user_data` 上传 32,812 字节探针，网关返回 HTTP 400，称缺少 model；标准 Files 上传不要求 model，因此该路径没有通过兼容测试。大文件 Files 尝试也在传输途中断开。没有得到文件 ID，未能继续验证 ID 引用。当前应使用已验证的内嵌 PDF 路径，不能依赖未验证的文件 ID 路径。

OpenAI 官方 PDF 输入会同时处理提取文字与页面图像；每文件小于 50 MB，单请求合计 50 MB，还占用模型上下文。官方服务能力与限额不等于第三方网关的完整承诺。[文件输入说明](https://developers.openai.com/api/docs/guides/file-inputs)、[文档核对记录](D:/CodeAndDesign/CowAgent/docs/codex/logs/2026-11-11-PDF原生接口资料核对.md)

## 采用建议

1. 对当前配置下能在请求与上下文预算内处理的 PDF，优先内嵌原生 PDF，让主 Agent 直接理解图文并组织知识，保留原件、用途、版本及出处登记。
2. 对大文件先考虑按章节或多页区间拆成几份 PDF；每批仍由同一模型同时理解文字和图像。上传超时与接口限额应单独处理，避免误判成模型不支持 PDF。
3. 对模型明确读不清的小字、复杂公式或图形，按需渲染该页或局部再识别；保留当前续处理、缓存与失败记录能力。
4. 已有可用知识及解析缓存时，优先复用；本次结论不要求每次提问重新上传全书。

这不是已实施的改造。新增原生输入还需接通消息内容转换、任务绑定、来源页码校验与失败回退；本次没有绕开现有知识发布约束。

本组真实原件没有覆盖中文正文，也未发现可确证的整页扫描文件；扫描能力由无文字层探针验证。Word 内嵌图形与其他格式未纳入本次测试，不能据此宣称已解决。
