## O-04 reading service（用户追加授权）

2026-11-12：追加授权生产 `agent/knowledge/reading.py`、`tests/test_reading_registry.py` 及 Wiki 来源守卫附近的配套修改。本代理未修改 read／knowledge_ingest／worker／材料／媒体／capability／SourceService／catalog／backup；这些由主代理及其他协作者整合。未启用默认原生路线，未 Git 提交，所有本地验证使用临时根并禁止网络。

接口 `ReadingService(workspace_root, task_store=store)`，同时导出 `ReadingRegistry` 别名：

- `prepare(task, receipt, base_parse, materials)`：接收真实 `PreparedPdf` 或 `to_dict()`，核验登记身份、来源状态、不可变 parse 和材料。重复准备复用记录；相同任务／材料／base 的旧 attempt 成功产物自动建立受信接续；无成功产物不能伪装为已读。
- `get(task, reading_id)`、`for_task(task)`：仅当前 running 任务且原 attempt 或已接续身份可读。终态审计采用只读 SQL，不把终态恢复成可写任务。
- `resume(task, reading_id)`、`resume_all(task)`：受信恢复器显式关联新 attempt，不改产生身份；原 attempt callback 仍在 TaskStore 屏障拒绝。部分成功批次保留，未发送批次可由当前身份建立新媒体引用。
- `media_reference(task, reading_id, segment_id, identity=..., provider_identity=...)`：返回真实 ToolMediaReference；核对实际 protocol/model/endpoint hash/RuntimeIdentity/task/config 和已验证 supported 能力；load 重验材料／范围／预算，随后只展开 PDF 字节，不写日志或历史。
- `save_response(task, reading_id, segment_id, response)`：在媒体 `on_response` 回调保存仅含 `id/output/usage/status` 的真实模型输出。保存哈希、完整 output 和 usage；拒绝请求输入及 data URI。成功回调后才标 completed；若响应已保存但最终回调前中断，同 attempt 再次 prepare 或新 attempt 受信 resume 可补完成凭据。只收到完成标志时明确 `completion_only/full_response_saved=False`，不以本地回执 ID 冒充服务商 response_id。
- `resolve_evidence(task, submission_id, evidence)`：严格六字段输入，返回 `{(reading_id,evidence_key): 四元出处}`。全提交载荷和逐别名完整载荷规范比较；来源／原件／副本／parse／响应哈希、成功送达位置和当前授权逐项验证。SQLite 事务提交别名与解析头；存储中断只可能留下不可见内容寻址孤儿文件，重试不覆盖、ordinal稳定。

sources schema 创建阅读表后设为2，task schema保持1；已有未知 reading 版本在初始化写入前拒绝。主代理负责 SourceService 版本屏障与完整备份兼容。

Wiki `_source` 对新 reading 单元调用 `verify_reading_unit`，保留 `type/origin/model_identity/reading_id/reading_copy`，旧单元快照形状不变。`read_reference` 为新 reading 原件返回当前数据根的哈希路径；原件哈希从当前来源根校验。阅读副本路径／hash／page_map 为稳定相对身份。历史档案守卫由主代理在 catalog 配套复核，未绕过其验证。

恢复演练采用真实 `create_backup_archive`／`restore_backup_archive`，由备份入口迁移旧 revision 的绝对原件字段；直接复制 SQLite 后删除旧根会被既有 catalog 历史守卫拒绝，这不是降级绕过守卫的理由。观察保存后再次经真实 reading_flow 准备，验证其 `source_native_parses` 锚点保持 base parse、材料哈希和 reading_id，不因新增模型观察版本而重复发送。

## V-25 跨任务缓存补充

用户追加要求后，prepare 增加跨任务复用：仅同 owner、逻辑 document/revision、base parse、完整材料 manifest、config 且来源有效、全部批次已成功完成并保存完整 response 时可复用。新任务始终创建自己的 reading_id；记录 `reused_from={reading_id,task_id,attempt,model_identity}`，不继承旧任务的阅读授权，不改原模型 output 中的 reading/task ID。每段 `saved_model_output_context` 明示 original 与 current 身份；旧 reading 不修改。新任务应以新 reading_id 提交新的观察别名。Wiki 回读新缓存来源同时提供 reused_from，守卫复核模型输出哈希及可信缓存关联。

新增测试覆盖新身份观察／发布、旧 ID 冒用拒绝、旧 output 原样保留、同任务重复准备幂等；不同 logical document 即使字节相同、不同配置、不完整或只有完成标志、来源撤回、响应篡改均不得复用。当前有界实现要求整份 manifest 的所有段完整成功；跨任务局部缓存拼接、跨配置模型兼容重用不在本增量中，不把不同资料身份合并为一份来源。

空 evidence 契约扩展为0～100项：无论是否存在观察，resolve_evidence 都原子核对／保存完整提交指纹，返回空映射时不产生解析单元。主 ingest 必须始终调用，不能用 `if evidence else {}` 绕过已有观察提交检查点；专题测试覆盖 drop_evidence。
