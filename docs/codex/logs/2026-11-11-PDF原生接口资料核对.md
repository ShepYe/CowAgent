# PDF 原生接口资料核对

核对日期：2026-11-11。此文件仅记录下列已打开的 OpenAI 官方文档，不包含主会话另行执行的网关与真实模型测试。实测结论见同目录《2026-11-11-PDF读取方案对比.md》。

**文档事实**

- GPT-6.1 Sol 的 API 标识为 `gpt-6.1-sol`，支持文本、图像输入及文本输出；上下文 1,050,000 tokens，最大输出 128,000 tokens。结合视觉模型的 PDF 输入规则，可确认其具备原生 PDF 输入能力。[模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[文件指南](https://developers.openai.com/api/docs/guides/file-inputs)
- PDF 的提取文本与页面图像都进入上下文。Responses 用 `input_file`，支持 `file_id`、base64 `file_data` 或 URL；Chat Completions 用 `file` 内容块，支持前两者，不支持文件 URL。每个文件须小于 50 MB，单请求全部文件合计上限 50 MB；所读指南未列独立 PDF 页数上限，仍须满足上下文限制。[文件指南](https://developers.openai.com/api/docs/guides/file-inputs)
- Responses 的 PDF `detail` 仅接受 `auto/low/high`，只影响页面图像，提取文本仍包含；GPT-5.6 及以后 `auto` 使用 `high`。Chat Completions 的文件输入不支持 `detail`。不能据普通图像接口支持 `original`，认定 PDF 也支持。[文件指南](https://developers.openai.com/api/docs/guides/file-inputs)
- Standard 短上下文每百万 tokens：输入 $2、缓存输入 $0.10、输出 $10；输入超过 272K 时，整请求输入及缓存费率乘 2、输出乘 1.5。PDF 文本与图像消耗输入 tokens，图像不是免费附件；不能按 PDF 字节数或页数直接算价。[模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[价格页](https://developers.openai.com/api/docs/pricing)、[视觉计费](https://developers.openai.com/api/docs/guides/images-vision)
- Files 先以 multipart 上传，再引用 ID，建议 purpose=`user_data`；上传端单文件最高 512 MB，非 batch 文件默认保留至手动删除，可设置过期。内嵌 base64 随模型请求传文件数据，省去独立上传步骤；两种路径都受 PDF 输入限制，ID 不代表免上下文计费。[上传参考](https://developers.openai.com/api/reference/resources/files/methods/create)、[文件指南](https://developers.openai.com/api/docs/guides/file-inputs)

**证据边界与推断**

视觉指南给出的普通图像限制为总 payload 512 MB、最多 1,500 张；这是图像输入规则，不能转写为 PDF 页数承诺。该页缩放表及 token 倍率表未列 GPT-6.1 Sol，不能套用 Astra 或 5.6 Sol 的数值；小字、旋转、图表识别仍可能出错，原生输入不保证无损识别。[视觉指南](https://developers.openai.com/api/docs/guides/images-vision)

上述事实描述 OpenAI 官方服务。工程推断：第三方“OpenAI 兼容”名称不足以证明其支持 Files 上传、ID 引用、PDF/base64/URL、detail 透传、同样的页面处理、限制、计费或真实模型映射；这些均须网关自身文档或另行授权的测试确认，本次没有确认。[适用范围依据：官方文件指南](https://developers.openai.com/api/docs/guides/file-inputs)
