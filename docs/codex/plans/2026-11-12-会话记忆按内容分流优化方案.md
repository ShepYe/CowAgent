# 会话记忆按内容分流优化方案

日期：2026-11-12，Asia/Shanghai。状态：专项文档复核通过，可按任务依赖实施；产品尚未实现。本轮仅审核并提交方案文档。

业务与持久化契约唯一正文为[规格 6.1／PA-18，MR-01～08](../../../.scratch/personal-assistant-foundation/spec.md#61-会话记忆按内容分流2026-11-12-方案pa-18)，执行入口为[工单 19](../../../.scratch/personal-assistant-foundation/issues/19-conversation-memory-routing.md)。本方案记录实现选择、顺序与验证，不替代规格；MR-01～08 是待实施契约，不表示能力已经运行。

## 1. 目标与问题依据

目标：同一个会话可以正常处理资料，也可以记住独立的个人偏好、约定和有价值的普通交流；测试、临时内容继续只留档，资料结论继续保留可核验出处。

当前 `agent/knowledge/purpose.py` 的 `_sourced_sessions` 把读过来源的会话持续标记。`durable_messages()` 遇到该标记，或一批消息中存在来源／临时标记时，返回整批空列表；`guard_memory_write()` 和 `write_daily_summary()` 也按会话整体阻止。已经用同一 session 下“读取来源后，提交一条普通偏好”的最小程序复现：普通消息保留数为 0。

聊天原始留档由 `bridge/agent_bridge.py`、`ConversationStore.append_messages()` 继续保存，与上述记忆提炼过滤不同。截图中 VNA 测试过程直接写日记被拒绝是合理结果；错误在于限制扩大到了后续普通聊天。

## 2. 用户可见行为

| 输入或场景 | 推荐行为 |
| --- | --- |
| 读完 VNA 资料，随后说“以后回答简洁些” | 记住回答偏好，不要求换会话，也不例行询问是否记住。 |
| 同一句话说“以后多用表格，这次测试预算是 42 dB，不要记” | 分开处理，只提炼真实偏好；测试数值和测试过程只留档。 |
| 讨论原件中的技术结论，或用户说“记住刚才资料里的数值” | 按来源知识处理，核对当前来源及用途，通过既有 `knowledge_ingest` 发布；不复制到无出处的个人日记。 |
| 用户提供自己的真实信息、决定或普通交流中的有效约定 | 根据价值正常提炼。助手推测或复述本身不能成为新的事实依据。 |
| 附件处理任务／自动测试生成的过程、结果和模拟人物偏好 | 只留档。不能把 worker 生成的“用户偏好”当成用户本人说过的话。 |
| 无法判断是真实偏好、测试样本还是资料派生结论 | 该条暂不进入长期记忆，其他明确条目照常处理；只有影响当前任务时才具体澄清。 |

“可以记”表示有资格参与提炼，并不要求把每句闲聊都保存为长期记忆。测试用途按实际任务或内容范围延续；普通新一轮消息不能自动解除仍有效的测试约束。

## 3. 推荐结构：保留原话，提炼条目，再分别保存

### 3.1 以一条候选事实为判断单位

主 Agent 依据用户原话、必要前文和已读来源，提出需要记住的条目，同时给出其依据。归类由模型理解语义，不使用“喜欢”“记住”等关键词白名单。程序负责验证依据、用途和归属，执行写入。

每条候选只表达一个独立事实，分为四种去向：

| 去向 | 内容与处理 |
| --- | --- |
| `conversation_memory` | 独立的真实偏好、约定、个人信息或有价值的普通交流；通过统一记忆写入服务进入日记／长期记忆。普通交流产生的独立主题知识仍按既有知识整理规则保存。 |
| `sourced_knowledge` | 资料原文及其派生结论；沿用来源用途、版本及 `knowledge_ingest` 发布，不生成第二份无出处记忆。 |
| `archive_only` | 明确测试、临时材料、模拟内容及其派生过程和结果；保留原始历史，不参与记忆摘要及 Deep Dream。 |
| `undecided` | 依据、用途或语义关系不足；保留待处理状态，不阻止同批其他条目。 |

不能仅凭候选自报 `conversation_memory` 就放行。须核对原话及必要前文：引用资料的话、用户复述的资料结论，以及“刚才那个数值”这类承接关系，都不能通过改个类别绕过来源规则。同一消息有两种用途时，引用各自的文本片段，而不是把整条消息统一放行或删除。

### 3.2 保存原话依据和统一条目状态

按 MR-02～04，复用 `ConversationStore` 所在 SQLite，增加版本化的记忆条目、用途决定和提交操作记录，不再建设聊天库。对新功能，台账统一保存正文、依据、有效状态和派生关系；聊天 `extras.memory_trace` 保留可回查关联，Markdown 与索引是可重建投影。

- 原始消息和事实候选先取得稳定身份；同事实经主动记忆、摘要、重启重提炼时，先解析已有候选，不能每次随机创建新身份。片段引用、修订及幂等键按规格核验，同字不同用途不互相吞并。
- 主 Agent 的有效用途决定与摘要候选分开保存。摘要只提候选；无有效判定时待处理，正常主 Agent 或受信记忆整理运行再判断。判定、待处理候选和必要前文引用在消息裁剪前保存，不因模型不可用而直接写入规则摘要。
- 用户更正、改为临时或明确排除时，台账在同一事务更新旧条目及其派生关系。原文保留历史，检索、提示注入和 Deep Dream 统一过滤失效内容；不能只更新主记忆、留下旧日记继续召回。
- 自动合并保留所有输入的候选与提交身份。即使回执尚未返回、正文已被 Dream 合并，重启重试仍可对账。

普通偏好必须有对应的真实用户依据；真人说过的测试台词也不能仅凭身份通过。资料身份、状态与派生关系沿既有受控来源服务核验，不由模型直接填写可信引用。压缩和合并不洗掉已有依赖。

`_sourced_sessions` 不再作为整场会话的永久否决条件。可保留为“当前提炼需要核对来源关系”的运行提示，最终准入取决于具体条目；不能在每轮开始时简单清空，也不能把整个会话的所有来源强加给每条独立偏好。

### 3.3 所有自动记忆入口使用同一个判断结果

建立统一的记忆写入服务，接收带可核验依据的候选，返回逐条结果。主 Agent 主动记忆、自动摘要、`/compact`、上下文溢出恢复和 Deep Dream 都通过它执行。

- 主 Agent 主动记偏好时，通过 `memory_record` 提交条目和依据；请求与逐条回执遵守 MR-03。
- 通用 `edit`／`write` 继续处理工作文件。对受保护的记忆目标，不能仅凭文件路径和任意 `newText` 直接改变长期内容；应走统一服务，并给出可操作的工具提示。现有知识写入同时维持受控来源与普通交流知识的边界。
- 自动摘要先形成独立候选，关联有效的主 Agent 用途决定后才可提交记忆；缺失或过期则保持待判断。不能把整批摘要先写入，再指望 Deep Dream 删除测试内容。
- 上下文压缩可保留完成当前任务所需的临时信息；“供本轮继续推理的摘要”与“可持久记忆的条目”分别输出。二者可复用同一次模型请求，不能再把同一段压缩摘要无条件写入日记。
- Deep Dream 只整理已准入条目，合并后保留其依据；不能自行从原始留档中补充资料事实，或把缺失依据的旧摘要升级成可信新记忆。

Markdown 投影为记忆块保存格式版本、权威修订、条目／输入提交身份及正文哈希，正文仍正常阅读；渲染、索引和提示词忽略机器标记并核验权威有效状态。程序先在 SQLite 原子提交，再生成文件投影；投影失败可重建，不撤销已接受条目，也不误报投影已完成或已经可检索。

本机用户通过现有工作区编辑器手动修改记忆，按既有权限保留；受控知识目录继续只读。人工保存也先提交台账的 `human_edit` 修订，不能只改文件或冒用旧依据；与自动整理共享冲突检查。外部文件改动按 MR-06 保留，停止不可靠的自动覆盖，不静默变成已核验的新事实。

逐条回执区分“已记住”“投影待完成”“仅留档”“需要按来源发布”“待判断”“写入失败”，是否可检索单独核验。正常的测试内容分流不展示成红色程序故障；实际调用不适用的写入工具仍返回明确的业务阻止，不能伪报成功。界面只显示简短结果，原因尽量放在问号悬停或工具详情中。

## 4. 重启、并发和旧数据

1. **标记完整保存。** `ConversationStore` 目前恢复 `extras` 主要依赖 `personal_task_id`；需要明确恢复新记忆元数据。检查提前保存用户消息、流式步骤、最终回复、子代理快照和恢复加载，不能只在回复结束后补标记。工具结果或压缩摘要使用的 `role=user` 包装不能被当成用户本人发言，必须保留真实来源和片段用途。
2. **冻结异步输入并串行提交。** worker 持不可变依据、身份和判定快照。个人记忆提交与用途／更正提交在同一数据库事务屏障内重核并更新，不能“检查完用途，再单独拿文件锁”。回调及投影另核权威记忆与上下文修订，迟到结果不注入新上下文。
3. **可重试且不重复。** MR-03 定义跨入口候选复用及同键同载荷／异载荷行为；MR-04 的权威操作记录与合并后的输入身份共同支持断点对账。成功接受与投影完成分别处理，失败不消耗重试资格。文件使用共享锁、基线哈希和严格原子替换；不能复用通用写入函数可能原地覆盖的降级分支，把损坏投影当成有效文件。
4. **统一失效。** 资料发布／撤回保持既有来源屏障；个人条目更正／排除以记忆台账为准，旧日记、派生块、提示及索引全部核验，混合块重算或拆分。独立偏好不因同会话资料撤回而失效；改为临时用途的偏好也不因重启或再次 Dream 复活。
5. **旧数据保留。** 按 MR-06 区分 legacy、已明确更正旧块、外部改动和格式损坏。旧任务用途标记继续识别，缺字段不等于全部可记；保留原文，但明确被更正的旧块退出当前使用，不能和新偏好永久冲突共存。
6. **需要时定向补提炼。** 对用户指定的历史范围，从真实留档重新判断，生成有依据的新条目；不扫描全部私人历史，也不自动把旧来源会话整体解禁。结构化标记损坏或版本未知时保留原文件，停止该文件的自动改写并提供诊断。
7. **备份和回退。** 完整备份覆盖会话库中的记忆台账一致快照、原话／用途元数据和文件投影。按 MR-07 在新根核验引用及权威修订，再重建过期投影／索引；旧读写器不兼容时使用升级前恢复点回退。临时工作区标识及业务身份恢复后保持，不把绝对磁盘路径当成记忆身份。

## 6. 验收场景

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| A-01 | 同 session 先读真实来源，后说“回答简洁些” | 偏好写入成功并可召回；来源事实未被复制到日记。 |
| A-02 | 同一消息同时含真实偏好和明确不要记的测试数值 | 只写入真实偏好，回查可定位其原话片段。 |
| A-03 | 测试样本里写“用户喜欢长回答”，模拟用户与工具输出各一份；之后用户真实表达同样偏好 | 测试样本不能成为本人偏好；测试约束按实际范围延续，之后的真实偏好不被旧文本去重吞掉。 |
| A-04 | 资料结论被助手改写、用户复述或跨轮指代；工具消息随后裁掉 | 来源依赖保留，只能走受控知识路径。 |
| A-05 | 一批历史同时包含普通交流、临时任务和来源任务 | 可独立提炼普通内容，不整批丢弃，也不整批放行。 |
| A-06 | 自动 trim、overflow、手动 `/compact`、日终摘要、Deep Dream；压缩摘要注入 user 消息 | 同一输入的持久记忆准入一致；包装角色不改变用途，临时上下文连续性不因禁止持久化而丢失。 |
| A-07 | 处理中重启、更换 Agent 实例、子代理快照及异根恢复 | 条目、依据、用途、身份一致；无凭空放行或重复写入。 |
| A-08 | 资料撤回／改为临时；同会话存在独立偏好 | 资料相关知识失效；个人偏好仍可用。 |
| A-09 | worker已重核用途后、提交前，用户提交排除／更正；撤回来源或切换上下文；两个worker交错 | 共同事务屏障识别胜出修订；旧判定不后提交，不注回新上下文，不串身份、不丢新增条目。 |
| A-10 | 跨主动／compact入口及重启后重提炼；权威提交后投影失败，回执前失败→Dream合并→重启重试 | 同事实复用身份，合并保留去重操作；已接受事实可对账，投影可重建，部分回执及可检索状态真实。 |
| A-11 | 旧日记无用途标记、旧任务带前缀、记忆块元数据损坏／未知版本；人工或外部修改记忆块 | 原文保留；旧任务继续排除，未知内容不自动升级；合法人工修改仍可保存，不冒用旧依据，元数据不可靠时停止自动覆盖。 |
| A-12 | 模型伪造依据、跨身份引用、把来源结论或真人测试台词标成偏好；缺失／过期主Agent判定 | 伪造及跨身份引用被拒；无有效用途判定只待处理，摘要自报不能放行；语义误分类由真实模型反例验收识别。 |
| A-13 | 旧偏好已进日记和主记忆并合并派生，用户更正后重启、重建索引、再次Dream；更正legacy旧块 | 旧原文可追溯，但全部当前检索／提示／整理不再返回旧决定；混合派生块重算或拆分，新偏好保持有效。 |

先运行离线回归和故障注入，再用临时工作区进行真实模型验收，不向真实个人记忆试写。语义分类仍依赖模型；原话定位与程序校验能约束归属、出处和用途，不能仅凭类型正确就宣称模型理解一定正确。

成本上复用现有摘要请求返回结构化候选，主动记忆复用当前主 Agent 的工具调用，不为每条聊天另起分类模型；缺少必要用途判定时按 MR-02／08 经受信整理运行补判，记录额外调用。真实验收比较原流程与新流程的请求次数、耗时、成功记忆和错误收录情况。
