# 知识库检索与使用体验优化方案

创建：2026-11-11；修订：2026-11-12，Asia/Shanghai。状态：按“目前无向量模型”修订，文档复核通过；当前主线可独立执行，产品未实现。业务规则唯一正文为[规格 5.9／PA-16](../../../.scratch/personal-assistant-foundation/spec.md#59-知识检索与使用体验优化2026-11-11-方案pa-16)，执行入口为[工单 17](../../../.scratch/personal-assistant-foundation/issues/17-knowledge-retrieval.md)。本方案记录技术选择、顺序、验证及剩余问题，不替代规格。

当前目标：无需向量模型，先完善标题／摘要／正文词项查找、同页证据融合、当前版本导航和恢复。保留现有目录、原件、出处与版本，不重新生成整库。向量语义检索是独立可选后续，不作为当前交付依赖或验收条件。

## 1. 依据与当前状态

- [官方知识库文档](https://docs.cowagent.ai/zh/knowledge)已支持主题 Markdown、自动整理、交叉引用、图谱及 memory_search 语义检索。优化沿用这些能力，不再建设一套相同的知识组织系统。
- 当前 `agent/memory/manager.py` 排除普通文件索引的 knowledge/wiki 命中，再接 SourceService 的权威关键词结果；`agent/knowledge/wiki.py` 目前按英文词及中文双字片段匹配。打开 embedding_enabled 不会自动让托管页获得语义召回。
- 托管桥接目前统一填 1～1 行，融合却按 path＋行号去重；同页不同正文块可能碰撞。托管关键词追加在普通结果后，顺序还影响排名。应先修候选身份和融合，再评价向量收益。
- 工单 14 及其[交付记录](../logs/2026-11-11-资料与知识界面优化.md)已记录资料／目录／分类／历史及异根恢复。[工单 15](../../../.scratch/personal-assistant-foundation/issues/15-knowledge-page-summary.md)已在 d58acc51 完成摘要实现及验证；本任务复用其字段、组件和兼容规则，原交付记录中的像素验收与真实问答留证边界继续保留。
- [文档读取方案](2026-11-11-文档读取与知识入库优化方案.md)及工单 16 覆盖主 Agent 原生阅读、Office 阅读副本和阅读证据。本任务直接消费有效发布结果，检索实施不等待全部格式接通，也不重复实现读取管线。
- 依据现有第 7 节和 [ADR-0001](../../adr/0001-local-sources-cloud-context.md)，Embedding 独立绑定、显式启用。用户于 2026-11-12 补充目前暂不具备向量模型，当前主线不要求配置此能力。

## 2. 用户实际得到什么

| 场景 | 优化后行为 |
| --- | --- |
| 问“怎样消除连接线对测量的影响” | 当前先查问题词项；结果不足时由既有主 Agent 尝试“去嵌／参考平面”等有目的检索，回读原文验证。任意改写的语义召回留给后续向量阶段，不保证关键词自动理解所有说法。 |
| 同一页中两段知识各有不同来源 | 两段均能进入候选，保留各自出处；页面展示去重不吞掉证据。 |
| 同一主题发布新版本 | 日常打开同一主题的当前版；从历史进入仍看原版本。 |
| 没有向量模型或本地离线检索 | 当前词项检索、目录和历史正常工作，无“待配置向量”故障；生成对话答案仍取决于当前会话模型是否可用。 |
| 恢复备份 | 当前先验证原件、解析、版本和引用完整；未来若增加向量缓存，该缓存可丢弃重建，不要求重整知识。 |

知识目录继续显示标题、分类和一句话摘要；历史和资料管理沿用现有入口，补充说明放问号悬停。当前目录的本地文字筛选继续匹配标题／分类／摘要，首批不把该输入框改成每次输入都会请求模型的语义搜索框；自然语言检索先由 memory_search 统一提供。

## 3. 推荐技术路线

当前链路为：词项查找 → 主题页／正文块候选 → 有效性核验与排名去重 → 回读正文及原件 → 回答。新增知识词项分支的查找与排序在本地完成，不调用模型；统一入口中原已配置的普通 memory 向量／重排能力按原设置保留。无向量整链验收明确关闭 Embedding 和 rerank，不静默修改用户旧配置。后续若具备向量模型，再增加一个候选通道，继续复用同一有效性和出处规则。

### 3.0 当前主线：加强本地词项检索

先沿现有 wiki 发布记录查询标题、版本摘要和 wiki_units 正文，不新增词项权威库；只有容量实测显示需要时，才另案采用可重建 FTS 缓存。查询副本做大小写、全半角及技术词分隔规范化，原文、行号和出处保持不变。优先完整词组、准确技术词，再按命中覆盖度与标题／摘要／正文字段生成排名；旧页无摘要仍能按标题和正文找到。

短词 VNA／RF／S11／S21 和“参考平面”等完整词组单独做样例；英文采用词项边界，避免 RF 误中 performance 一类长单词；仅采用资料明示或用户提供的中英／缩写别名作查找辅助，不维护未经来源核对的常识同义词库。页级选页提示、正文块命中及其身份／定位／缺省契约统一按 KR-08：page 不携块出处；已有同页 block 时合并选页排名线索而不额外占位，工具始终标示“选页提示，须回读”。正文块即使只能提供整页 Markdown 行范围，也保留 block 身份与真实出处，定位精度另记 line_precision。旧调用方维持原返回语义。

通常检索一次；缺口才由现有主 Agent 追加词项，不单独调用改写模型。三次预算的作用域、受信轮次、失败与重复计数、第四次 retrieval_budget_exhausted、暂停／新 attempt／重启重置均以 KR-08 为唯一规则；K-07 在工具边界执行并验证，不能只改提示词。额外工具轮次有成本，记录次数和时延；到预算后回读已有候选或说明缺口。

### 3.1 后续可选：在现有进程中增加独立向量缓存

复用 `agent/memory/embedding/factory.py` 的能力绑定、embed_batch/embed_query、现有 SQLiteVectorBackend 与分块器。每个消费方 Agent 在自身 memory/long-term/knowledge-search 下存放代际清单及独立 SQLite 缓存，不写入通用 index.db 的向量空间；缓存记录按 KR-03 保存正文块／子块身份，向量存储适配不反向依赖 knowledge 的发布实现。实际权威知识根按现有自有／共享规则解析，切换根先使活动缓存未就绪。清单以发布身份、哈希及来源快照绑定实际权威数据；绝对路径不参与可迁移身份，不仅凭目录同名或标题复用。异根恢复保留缓存时也重新比对全清单，仅复用匹配单元，不额外引入可修改的知识身份库。

已有 SQLiteVectorBackend 依赖 chunks 表和调用方事务，不能仅换数据库文件名就假定支持完整发布信息；K-02 通过薄适配保留块身份，必要的附加元数据与指纹均属缓存，不重建整套 MemoryManager 或权威来源库。若首次容量探针不能满足第 5 节目标，先优化同进程批量及本地索引，不直接引入独立向量服务。

Embedding 输入使用标题＋摘要＋一个正文块；长块按现有分块预算细分并保留上级位置。分类调整不改变输入；旧页无摘要可用标题和正文，不调用模型补摘要。禁止将 source_reference JSON、内部编号、历史版本或解析全文拼进向量输入。原文补读依旧经过现有来源守卫。

发布成功后登记待补向量，后台批量构建、重启对账；关键词可用即维持原发布回执。语义就绪单独报告覆盖度。构建与查询绑定配置修订，完整指纹贯穿请求缓存和索引代际；避免直接调用会清空通用索引的既有 rebuild 路径。

### 3.2 当前先修候选身份，后续再接向量融合

区分存储身份与融合身份：向量缓存精确到页版本＋正文块＋子块，正文块融合回到页版本＋正文块；页级提示按 KR-08 的独立身份归并。向量通道按同块最高子块相似度排序，所有命中位置保留，再与关键词整块去重；普通文件保持原身份。向量和关键词转结果前从发布记录补真实出处，并计算已核验不可变 Markdown 的真实行区间；旧格式无法唯一映射时返回整页实际行范围并标明页级定位。扩展 memory_search 显示与按行回读验证，不把块编号当作行号。多个子检索器按稳定排名合并，同一通道先统一排序，再沿用现有“按命中通道归一融合”的语义；不拼接异种原始分数。普通 memory 的阈值、单通道命中和旧返回格式有回归保护。

新增词项分支不初始化 reranker，也不单独调用模型改写查询；统一入口原有显式配置的重排保持。词项分支的不同查询按稳定块身份去重；资料明示别名及主 Agent 按需用词仅辅助找页，不写入知识正文。3.2 中的向量子块聚合在后续实施向量时才验收；当前先验证不同正文块不互相吞并、同块多查询不重复以及真实行号回读。

### 3.3 后续可选：向量代际切换与失效控制

新指纹使用新代际；旧代际保留。构建完成后核验覆盖清单，补齐构建期间的新发布并排除失效项，最后在缓存库内原子切换活动指针。跨来源库和缓存库不伪装成一个事务：切换前核验清单，查询及回答前仍核验来源；切换后出现的新页先走关键词，后台再补向量。

构建断点至少能识别代际、完整指纹、配置修订、已完成输入哈希及失败批次。远端限流／超时只重试该批，数量、维度、有限值和输入顺序不符的返回不得入库。查询先固定原任务／即时入口捕获的配置修订，只选该修订明确绑定空间的代际；新 B 查询不调用保留的 A 服务，旧 A 查询不混 B 缓存。密钥轮换可复用相同指纹数据，但请求仍用该查询合法凭据。原任务修订不可执行时沿用 config_unavailable；通过配置检查但缺匹配代际时关键词降级，保留缓存供恢复。已关闭开关、旧 attempt 或旧指纹的迟到响应只可丢弃／留诊断，不切换当前代际。

撤回、更正和依赖暂停先改权威状态，缓存清理随后进行；构建、查询、重排和答案回读都有失效测试。允许恢复缓存，不允许以恢复缓存为由复活旧来源或退役 managed。

## 5. 分阶段验收与成本

K-01 在调参前固定至少 20 个主题、多个来源及干扰页的射频测试资料，保存相关页集合 R(q)、跨来源必需证据集合 E(q)（页版本＋正文块＋出处）及无依据标签。共 50 题：10 题原词、10 题同义改写、10 题中英文术语／缩写、10 题跨来源，以及 10 题库内无依据。每类按主题／来源分为 5 题开发集和 5 题保留集；相关主题不跨集。先冻结语料、标签、分集及计分协议，再采集关键词基线，不能看到结果后换题；当前真实资料仅作额外样本。

Hit@5 仅对 40 道有依据题按题计算前五个不同知识页是否至少有一页属于 R(q)。跨来源证据覆盖仅对 10 道 E(q) 非空的跨来源题计算 |已回读且有效的命中证据 ∩ E(q)| / |E(q)|，再取宏平均；其余题该项记 N/A，不将空分母计成零分或满分。各适用指标分别报告全体和保留集；无依据题独立判定，不混入 Hit@5 或证据覆盖的分母。另固定 12 个可复现词项缺口夹具：标题独有、摘要独有、短词边界、资料明示别名各 3 个，开发／保留各 6 个，不能据保留结果调权重。

### 5.1 当前无向量交付门槛

| 指标 | 当前通过要求 |
| --- | --- |
| 有效改善 | 12 个词项缺口夹具全部能在前五个不同页找到预期对象；标题／摘要提示不是正文事实。10 道原词题及其中 5 道保留题的命中不低于原关键词基线。 |
| 同义与跨来源 | 50 题均记录候选命中及适用性；Hit@5／证据覆盖按上述适用题集统计，其他记 N/A。任意同义改写、未明示中英等价关系作为诊断；已找到的多块／多源证据不被误合并，缺口保持可见。 |
