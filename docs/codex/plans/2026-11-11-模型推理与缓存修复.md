# 模型推理与缓存修复

## 目标与定向契约核对

修复微信／飞书共用模型层丢弃已保存的思考强度，以及 Responses 缓存统计丢失；为有会话身份的 Responses 请求提供稳定缓存键，并保证切换新型号时不因未登记型号而丢弃参数。本次是边界明确的兼容增量，不改变权限和任务状态。

- 思考强度仍优先读本模型配置，再读全局配置，项目全局缺省 `high` 保持不变。现代 GPT 家族和自定义 OpenAI 兼容供应商提供协议级通用档位；未核实型号按用户设置透传，不将“型号未知”判为“参数不支持”。已证实 `gpt-6.1-sol`、`gpt-6-astra` 及其日期快照的禁用限制作为例外单独维护，不扩散到未知新型号；未知型号关闭思考时省略参数，由上游决定默认行为。
- `auto` 协议识别采用 GPT 数字主版本规则，当前第 6 代及后续版本默认使用 Responses；显式 `chat/responses` 优先。自定义供应商支持可选 `api_type: auto/chat/responses`，缺省或非法值回到 `auto`，不读取其他供应商的协议设置，支持无需改代码的中转别名。
- Responses 缓存键通过供应商地址、模型和会话身份生成稳定哈希，适用于所有走 Responses 的型号，同会话后续轮次与运行标识变化不改键，不向上游发送原始会话／用户标识。无会话时省略；旧 Chat Completions 路径不增加字段。键仅帮助路由，不承诺命中率。
- `input_tokens_details`、`output_tokens_details` 分别保留为 Chat usage 的 `prompt_tokens_details`、`completion_tokens_details`。原有三个总量字段不变，旧响应未携带详情时保持旧格式；旧读者可忽略新增详情。
- 不改写用户保存的强度，不记录密钥，不新增本地持久状态；回滚代码无需数据迁移。代码生效需要运行中的 Python 后端加载新模块。

## 诊断证据

2026-11-11，使用当前中转配置和仅包含合成资料的相同 6,691-token 请求验证：上游正常回显 `reasoning.effort=high`。未带缓存键的 CowAgent 实际流式调用报告零命中；相同真实调用链补固定键后，两次均返回 `cached_tokens=6528`，经本次转换修复后归一化为 6,528 命中、163 未命中。非流式探针报告零命中；此结果说明中转对请求形态／路由存在差异，不能推导所有服务的流式开关决定缓存。

最终代码不改写请求体的完整验证：让 `AgentLLMModel` 自动产生新的会话哈希键，第一轮冷缓存命中 0，第二轮命中 6,528 / 6,691（97.6%），两轮实际发送 `high`。验证未向微信／飞书发送诊断消息。

只读前缀对照确认普通同日短文本追加可保持前缀；工具列表变化、日期变化、技能／资料更新及历史工具结果超过 20,000 字符后的裁剪会改变对应前缀。这些是命中率的条件性限制，本次未扩展为提示词或历史存储重构。

扩展兼容范围后的最终相关回归 358 项通过，修改文件 Ruff F 与 `git diff --check` 通过。`gpt-6.2-sol`、后续数字版本与自定义别名仅作为本地 HTTP 边界测试的占位名，验证参数构建、协议路由和缓存键，不代表已调用或核实未来上游型号。源码已完成；当前运行中的桌面后端尚未重启加载，新启动的真实调用探针已验证当前型号的上述行为。

上游参考：[模型能力](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[缓存规则](https://developers.openai.com/api/docs/guides/prompt-caching)。缓存仍受前缀、工具、上游路由与保留策略影响，实测命中不作为所有真实对话的命中保证。
