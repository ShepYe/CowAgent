# 知识页图文呈现改造方案

日期：2026-11-12，Asia/Shanghai。状态：F-01～F-07已完成，V-35～42验收通过；前三次失败及后续修复过程保留于验收记录。业务契约唯一正文为[规格 5.10／PA-17](../../../.scratch/personal-assistant-foundation/spec.md#510-知识页图文呈现2026-11-12-方案pa-17)，执行入口为[工单 18](../../../.scratch/personal-assistant-foundation/issues/18-knowledge-page-figures.md)。本方案维护实现选择、顺序与验证，不替代规格。

## 1. 用户将得到什么

知识页继续按主题整理，在结论、方法和公式旁插入支撑理解的关键原图／裁图，配简短图注及出处，点击可放大或回查原页。AI 自动选图和裁图，裁剪不可靠时在已核验范围内整页兜底，范围不足先补读；不需要用户逐图确认。AI 检索正文和图注后，需要视觉细节时实际读取图片，不能把图注当作已经看图。

PDF 原件、Word／PPT 已有 PDF 阅读副本共用同一页面图片处理能力；保留副本与原件位置映射，桌面与 Web 同步呈现。图片资产随知识版本保留，历史页能看当时画面，当前使用继续过滤失效来源。正文已核验但插图失败时先发布文字并标待补图，不报告整项完成。

现有只有一份 VNA 原件，用户已授权能力完成后直接重新生成图文知识，不做批量迁移。首期不新增携图离线导出、模型重绘或图片向量检索。原件、既有主题身份、手动分类与历史继续保留。

## 3. 实现组织与失败处理

### 3.1 来源材料到稳定图片

在现有 PDF／Office 阅读副本边界建立图片准备及资产登记模块。由程序验证 source、已交付阅读凭据、页与 region，再调用既有渲染器，生成不可变 PNG、相对身份及清单。程序维护文件身份，模型只选择要显示的部分与图注，不提交磁盘路径或图片哈希。读取缓存可以复用，但知识图片的长期存储不能仅指向临时阅读目录。

将图片准备／验证责任集中在新模块，Wiki 调用其发布校验，HTTP 和 read 调用其授权读取；两端不分别实现一套来源守卫。具体私有类和表列组织留给实施；KF-02～07 的公开字段、版本、状态和恢复语义保持一致。

### 3.2 正文、图片与任务三层检查点

1. 受信任务先保存本次正文及选图目标，图片资产先准备、验证落盘。
2. 来源库事务提交不可变图文清单、正文及发布指针；图片失败可以发布带 pending 清单的可靠正文。
3. 任务库以稳定提交身份对账回执和补图目标，阅读与配图目标均满足才提交 succeeded。

两库和文件不是跨介质原子事务，恢复依赖顺序、幂等键及检查点。补图生成新内容版本，旧 pending 版本作为历史保留；不得改旧正文后重新计算哈希来伪装原版本。正文、图注和 Markdown 的规范化输出使用同一来源，不给索引维护第二份独立事实。

有界执行预算耗尽后沿用 failed／publish、figure_incomplete 及已发布 result_refs，可按原配置重试；不新增永远轮询的状态，也不把补图错误误记为 pending_index。恢复先对账已提交结果，再只补缺口，沿用原 attempt 隔离、来源有效性、取消和配置屏障。来源／正文失效与派生 PNG 不可用分别处理，图片缺失不自动删除可靠正文或整库知识。

### 3.3 UI 与 AI 使用

两端 Markdown 识别受控逻辑引用，按当前／历史视图通过认证 API取图，并保留普通图片行为。图片懒加载、限宽，状态与说明紧凑展示；按 backend／Agent／发布身份丢弃迟到响应。图谱数据及布局不因图片状态或视图切换被无条件清空。

read 在通用路径解析前识别受控逻辑 URI，核验当前或显式历史资格、文件及来源身份，再交现有媒体层；按模型／协议能力选 PNG 或关联 PDF 片段，不切换未配置服务商。实际媒体发送、失败、visual=false、回读时撤回及上下文复用均要验证，避免只做到 UI 能看图。

### 3.4 兼容与完整恢复

先用隔离的 v1／v2 来源及任务库演练 v3 迁移，覆盖源库已升级、任务库未升级及相反顺序。所有入口（含只读 API、ReadingService、备份白名单及版本检查）同步更新。旧数据／候选不推断图片完成，图文新任务必须显式给出配图目标，旧输入不能默默绕过新完成条件。

完整备份保留当前／历史图片字节、清单、来源和任务关联；移动至新根后删除对原根的访问依赖再回读。派生图可按固定材料与渲染身份核验重建，清单及发布身份不能重建成另一个事实。旧程序只用匹配的升级前恢复点；本期不增加自动删除历史图片的动作。
