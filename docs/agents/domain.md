# 领域文档

## 探索前读取

采用 single-context 布局。探索代码或设计方案前，读取根目录 `CONTEXT.md` 及 `docs/adr/` 中与当前任务相关的 ADR。

这些文件不存在时静默继续。领域术语或架构决策被实际确认后，再由 `domain-modeling` 等技能按需创建。

## 文档位置

- `CONTEXT.md`：项目领域术语表。
- `docs/adr/`：已确认的架构决策，按编号独立成文。

## 使用规则

Issue 标题、规格、设计提案和测试命名沿用术语表中的词汇。遇到尚未定义的领域概念时，在领域建模过程中确认并补充。

提案与现有 ADR 冲突时，指出对应 ADR、冲突内容和重新讨论的理由，再处理该决策。
